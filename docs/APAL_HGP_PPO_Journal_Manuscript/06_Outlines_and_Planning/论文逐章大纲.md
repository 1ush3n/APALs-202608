## 全文暂定中心论点

本文面向 Aircraft Pulse Assembly Line（APAL）中工序、物理工位和技能约束工人团队的强耦合调度，构建 APAL 特定的异构图强化学习框架 HGP-PPO。与排程前固定工人—站位配置不同，当前实现令工人在初始时保持未绑定；策略先选择工序及其可行物理站位，再从未绑定或已绑定于该站位的候选工人中构造具体集合。工人首次被某站位选中后即形成永久站位绑定，使人员配置由排程中逐步显现的工位任务量和技能需求内生决定，同时避免后续跨站流动。HB-GAT-PN、Skill Hub、全局上下文池化、自回归指针解码和自适应可行性掩码将该联合动作转化为具有条件依赖的顺序决策。论文拟重点检验：仅使用有限的随机中等规模实例训练后，该策略能否无微调迁移到规模差异显著的实验室提供 APAL 基准实例，并在解质量、硬约束可行性和推理效率上保持竞争力。动态重调度作为同一架构经 warm start 和任务适配后的扩展能力单独验证。

|---|---|---|

| Heterogeneous Graph Pointer PPO (HGP-PPO) | 完整调度框架 | 用于指代状态建模、策略网络、动作解码和 PPO 训练的整体方法 |
| HB-GAT-PN | HGP-PPO 的策略网络 | 不与完整框架名混用 |
| APAL heterogeneous graph | APAL 异构状态图 | 在 Skill 为显式节点时包含 operation、station、worker、skill 四类节点，暂不称“tripartite graph” |
| Skill Hub | worker-skill-operation 的语义分解与稀疏连接结构 | 只有完成效率与质量消融后，才声称其降低图规模且保持调度质量 |

| schedule-endogenous worker–station binding | 初始排程中工人起始未绑定；选定工序与站位后选择具体工人，工人首次被选中即永久绑定到该站位 | 表示“站位需求驱动、逐步形成的一次性绑定”；不是工人主动选择站位，不包含后续跨站移动，也不得与 dynamic rescheduling 混用 |
| adaptive feasibility mask | 每个解码子步骤中的动态硬约束掩码 | 强调约束嵌入；可行性结论须由 eligible/valid 指标支持 |
| dynamic rescheduling | 在基准排程和扰动条件下进行局部重排 | 必须同时讨论解质量、冻结任务一致性、稳定性和硬约束合格率 |

# 第一章 Introduction

## 1. 本章功能

第一章不负责完整介绍算法细节，也不负责展开实验数字。它需要让读者依次接受五件事：

1. APAL 调度是具有明确航空装配背景的工业问题；
2. 其决策对象是工序、物理工位和技能约束工人团队的联合配置，不能直接等同于 JSSP/FJSP；
3. 现有装配线研究和通用学习型调度研究之间仍存在一个 APAL 特定的方法缺口；
4. HGP-PPO 的表示、解码和约束处理机制与该缺口逐项对应；
5. 本文将用初始调度、模块消融、泛化/效率和动态重调度实验验证这些主张，并诚实限定尚未完成的证据。

## 2. 本章核心论点

APAL 的部署可行性取决于对时间、空间和劳动力约束的联合推理。排程开始前尚不知道各站位最终承载的任务量与技能需求，预先固定全部工人—站位关系可能造成技能供需和工作负荷错配。因此，需要一种在生成排程时联合决定工序顺序、物理站位和具体工人集合的框架：工人最初未绑定，首次被某站位选择时形成永久绑定，使站位人员规模和技能构成由排程需求内生形成，并将 APAL 关系结构、高阶动作构造和硬约束检查共同嵌入策略决策过程。

## 3. 推荐叙事结构

采用“general-to-specific setting + technical-challenge”结构：先从复杂航空装配的调度需求收敛到 APAL，再拆解 APAL 的特定技术挑战，随后评述相邻研究为何不能直接闭合该问题，最后引出 HGP-PPO。该结构适合 APAL 这一相对小众、且容易被误解为 FJSP 的研究对象。

正式英文 Introduction 建议写成 6 个连续段落，不设置可见的 `1.1`、`1.2` 小标题。目标长度暂定为 900--1,100 个英文词。

### 审稿人为何应相信该框架“有必要”

引言不能把异构图、池化、Pointer Network 和 PPO 简单列成模块组合。需要建立三层必要性证据：

1. **问题结构必然性**：APAL 的实体类型、关系类型和联合动作结构客观存在，传统的 operation-machine 或单实体打分不能直接覆盖 operation-station-worker-team 决策。
2. **机制对应性**：每个模块只回答一个清晰问题。异构图负责保留实体与关系语义；Skill Hub 负责分解 worker-has-skill 与 task-requires-skill；全局上下文池化负责暴露跨实体的瓶颈状态；自回归指针负责条件化构造给定基数的具体工人集合；动态掩码负责逐步维持可行候选集。
3. **反事实实验验证**：通过统一训练预算下的简化模型和模块消融证明，如果移除某个机制，对应能力会出现可预测退化。没有这层证据，只能声称“提出了一套框架”，不能声称“这些结构对于 APAL 是必要的”。

联合动作规模建议在问题定义或方法章节写成：

```text
|A_flat(s_t)| = sum_{i in R_t} sum_{j in S_i(s_t)} |T_ij(s_t)|,
```

其中，`R_t` 为就绪工序集合，`S_i(s_t)` 为工序 `i` 的可行工位集合，`T_ij(s_t)` 为给定工序和工位后的可行工人团队集合。若有 `m_ij` 名候选工人且需要选择 `q_i` 人，在忽略技能组合等附加限制时，团队候选数的上界项为 `C(m_ij, q_i)`。因此困难来自团队组合数与上游工序、工位选择相乘。

必须准确表述：自回归指针网络**没有消除底层组合搜索空间**，而是将联合分布分解为连续条件分布，避免把所有可行团队预先枚举为一个固定动作表，并允许在每个子步骤更新掩码。

### 段落 2：APAL 的联合决策、决策时资源配置与问题边界（约 170--210 词）

**段落任务**：精确定义本文解决什么，并防止读者把 APAL 误读为普通 FJSP/JSSP。

**计划内容**：

- 给出每个决策时刻的核心联合动作：选择工序、分配物理工位、构造满足该工序技能与人数需求的具体工人团队；
- 解释为什么初始排程不预先固定全部工人—站位配置：在工序排序与站位分配产生之前，各站位的任务负荷和技能需求尚未确定，静态配置可能产生局部短缺与闲置；
- 准确定义动作方向：策略先选择工序与站位，再为该工序—站位组合选择工人；未绑定工人的第一次选择会形成永久站位绑定。因此这是排程内生、需求驱动的一次性人员—站位配置，不是工人具有独立的“选择站位”动作，也不是工人随后在多个站位间移动；
- 概括 precedence、pulse-line spatial monotonicity、station capacity/slot、worker skill、station-worker binding、worker availability 和团队协同加工等约束；
- 说明 JSSP/FJSP 的 operation-machine 建模可提供方法借鉴，但不能完整表达 APAL 的物理流动、工位与工人团队耦合；
- 明确本文不宣称提出通用 FJSP 求解器，也不把 APAL 简化为 operation-machine eligibility。

**所需证据**：本文的问题定义；APAL 与 ALB/JSSP/FJSP 的维度比较表；装配线问题 taxonomy。

**建议配图/表**：在 Introduction 或 Related Work 放置“APAL 与典型 ALB、JSSP、FJSP 的差异表”，具体位置待全文结构确认。

### 段落 3：四个技术挑战（约 170--210 词）

**段落任务**：把工业困难转译为可由方法回答的技术问题。

**计划内容**：

- **状态表示挑战**：前序、空间、技能、绑定和动态可用性属于不同关系类型，扁平特征难以保持实体与关系语义；
- **资源配置挑战**：工位负荷和技能需求由排程逐步内生形成，工人配置不能脱离工序与站位决策单独预先优化；
- **动作空间挑战**：operation-station-worker-set 联合动作随候选工人数量及工序需求人数 $q_i$ 产生组合增长，且不同工序的 $q_i$ 可以不同；
- **可行性与动态性挑战**：每个子决策都会改变后续候选集合，扰动重调度还需同时保护冻结任务和排程稳定性；
- 用一句过渡指出，方法必须同时解决“表示、构造、约束”三件事，而不能只替换优化器。

**所需证据**：动作空间的组合规模推导；本文环境约束；重调度场景定义。组合增长只能作结构性分析，不写成未经证明的复杂度结论。

### 段落 4：相关方法及未闭合缺口（约 170--220 词）

**段落任务**：综合现有研究，形成可检验的 research gap，而不是罗列文献。

**计划内容**：

- 第一条研究线：generalized assembly line balancing/scheduling 已揭示真实装配线中的异构资源和复杂约束，但通常依赖逐实例优化、启发式或特定规则；
- 第二条研究线：GNN/DRL 调度表明图状态和 learned dispatching policy 可提升快速推理与跨实例复用能力，但主流验证对象多为 JSSP/FJSP 的 operation-machine 决策；
- 第三条研究线：随机/动态调度研究处理加工时间或资源扰动，但 APAL 重调度还要求冻结任务一致性、站位约束和团队重构；
- 汇总缺口：已有 APAL/AFAL 研究常预先完成工序—工位划分、在单工位内调度，或将人员分配作为独立阶段；仍需检验一种统一学习框架，能否在排程生成时共同决定工序、物理站位和具体工人集合，使工人配置随站位负荷与技能需求内生形成，并通过逐步硬约束过滤保持可行。

**所需证据**：装配线综述与 taxonomy；GNN/RL 调度原始论文；随机/动态调度论文；航空装配重分配研究。

**证据缺口**：当前本地文献不足以支持“现有研究从未做过 APAL 图强化学习”的排他性断言。正式成稿前需开展专门检索，因此暂不使用 `the first`。

### 段落 5：本文方法、挑战应对与贡献（约 230--290 词）

**段落任务**：不再把“方法介绍”和“贡献列表”重复写两遍，而是沿用第三段提出的挑战顺序，以“挑战—具体机制—形成的贡献”逐项回答本文做了什么。

**计划内容**：

1. **针对异构状态表示挑战**：提出 APAL heterogeneous graph，以 Operation、Station、Worker 和 Skill 节点及关系特定消息传递表示前序、资源归属和技能供需；Skill Hub 用于显式分解 `worker-has-skill` 与 `operation-requires-skill`。其贡献是面向 APAL 多实体约束的统一状态表示，而不是单纯引入 GAT。
2. **针对跨工位全局瓶颈感知挑战**：以类型归一化的全局池化汇总可变规模节点，使任务选择能够感知站位负荷、关键工序和工人供给。其贡献是为跨实体竞争提供固定维全局上下文；注意力池化相对固定统计池化的实际增益由消融决定。
3. **针对联合动作组合增长挑战**：用自回归 Pointer 将 operation-station-worker-set 联合动作分解为工序、工位和给定人数工人集合的条件选择，避免显式枚举全部团队。其贡献是可变候选集合上的结构化联合解码，而不是声称消除了组合复杂性。
4. **针对资源配置与逐步可行性挑战**：通过 task/station/worker masks、事件驱动状态转移和首次选择后的永久工人—站位绑定，使人员配置随排程中逐步出现的任务量与技能需求内生形成。其贡献是把资源配置与工序排程置于同一生成过程，并在每个子决策后更新可行域。
5. **针对跨规模与重调度需求**：使用共享参数的可变规模图编码、归一化池化和 Pointer 候选打分，使同一策略可在不同工序规模上运行；再通过特征扩展、warm start 和继续训练迁移到物料扰动下的工序开始延误重调度。跨规模效果与重调度收益属于实验验证贡献，不能仅由结构设计自行推出。

本段末尾用一句话预告验证范围：同一 checkpoint 在约 283--3182 个物理工序的 APAL 实例上无梯度微调评价，并通过传统/学习基线、模块消融、效率分析和固定情景重调度检验上述贡献。当前可以称为**跨实例规模泛化/跨规模迁移**；若四个基准参与 checkpoint 选择，则应进一步说明它们是 cross-scale validation benchmarks，而不能称完全独立的 held-out test。

**所需证据**：方法章中的图结构、概率分解、掩码和绑定规则；实验章中的同 checkpoint 跨规模结果、分层动作基线、模块消融、效率和重调度对照。

**边界控制**：在实验完全结束前不写“全面优于 state of the art”；Skill Hub、GAT、池化和 Pointer 的必要性分别由对应消融限定；重调度只覆盖本文实际实现的物料扰动导致的工序开始延误场景。

- **主要研究缺口**：现有方法难以联合表达和解码工序—工位—工人团队约束；“APAL 专用学习框架”是对此缺口的解决方案，而不是更上位的独立缺口。
- **证据基础**：四个由实验室提供、规模覆盖约 200--3000 工序的 APAL 基准数据，以及随机生成的中等规模训练实例；传统方法和仅调度工序顺序的方法难以同时处理多资源联合派工。数据的工厂来源、采集方式和相互独立性尚未核实。
- **首要记忆点**：少量随机训练实例到未见 APAL 基准实例的跨任务、跨规模泛化；初始调度和动态重调度共享主要网络结构。
- **Skill Hub 定位**：Skill 是显式虚拟节点类型，用于聚合同技能关系；worker 节点仍需保留，因为工人虽具有一定可交换性，但在可用性、站位绑定和效率等属性上不应被假设为完全同质。

### Research Question 的含义

Research Question（RQ，研究问题）是整篇论文要用模型、实验和数据回答的核心问题。它不是论文标题，也不是贡献列表。一个可用的算法论文 RQ 至少应包含：

1. **研究对象**：在哪一种 APAL 调度设定中；
2. **方法干预**：采用什么类型的方法或关键机制；
3. **可观察结果**：评价解质量、可行性、效率或泛化中的哪些指标；
4. **比较或边界**：相对于哪些方法、在哪些未见规模或扰动条件下。

可按下面的句式自行填写：

```text
在 [训练与测试边界] 下，采用 [APAL 特定方法及关键机制]，
能否在 [未见 APAL 实例/规模] 上，相对于 [基线类别]，
同时获得 [解质量、硬约束可行性、推理效率]，并表现出 [目标泛化能力]？
```

根据当前讨论，主 RQ 应聚焦初始调度的联合决策与零样本泛化；动态重调度更适合作为次级 RQ，因为它使用相同架构但经过 warm start 和额外任务训练。

## 7. 泛化主张的证据门槛

当前可执行主配置使用 `data/scale_400_800_datasets` 中 80 个约 436--795 工序实例训练。283、680、2338、3182 四个实验室提供 APAL 基准被作者定义为约 200--3000 工序的跨规模验证集，而不是训练集。需要注意，`enable_multi_benchmark_eval=true` 会在训练期间评价四个基准，并可用综合分数选择 best checkpoint；因此当前协议能够支持“无梯度微调的跨规模验证迁移”，但不能直接支持“完全 held-out test”。另一个 `multiscale_initial_schedule.yaml` 虽写有 200--3100 训练范围，但其训练目录当前不存在，应视为未启用/遗留配置，不进入论文实验描述。

泛化证据分成两级：

1. **当前可成立口径**：每个随机种子只在 400--800 工序池上进行梯度训练，用同一个 checkpoint、无微调地评价 283/680/2338/3182；若四基准参与 best checkpoint 选择，统一称 `cross-scale validation benchmarks`；
2. **推荐的最强口径**：另建独立的 400--800 validation pool 选择 checkpoint，关闭四基准上的 best-checkpoint selection，再对四个基准执行一次性 held-out test；
3. 随机训练实例的来源、数量、规模范围和与真实数据的拓扑关系必须披露，排除复制、切分或模板泄漏；
4. 同步报告 makespan、feasible/eligible rate、推理时间和相对规模增长，而不是只展示一个成功案例；
5. 如需与按规模专门训练模型比较，应分成 `zero-shot policy` 与 `scale-specific policy` 两组，不能混在同一主表中。

## 8. 第二轮回答与论证结论

- **数据来源**：四个 APAL 数据集由实验室提供，具体采集来源和工厂对应关系未知；已知其工序规模约覆盖 200--3000。因此论文只能称其为 `lab-provided APAL benchmark instances`，在溯源完成前不得使用 `real-factory datasets`、`four factories` 或 `independent production lines`。
- **泛化协议**：确认采用单策略协议。每个随机种子在 400--800 工序随机实例池上训练一个策略，再使用同一 checkpoint、无梯度微调地评价 283/680/2338/3182 四个跨规模基准。当前四基准属于 validation；只有将 checkpoint 选择与其隔离后，才升级为 held-out test。按规模训练的 checkpoint 只能作为补充对照。
- **初始排程资源配置**：作者确认不在排程前预先固定全部工人—站位关系。策略先形成工序—站位决策，再在绑定和技能约束下为该站位选择具体工人集合，使人员配置随各站位逐步形成的任务量与技能需求内生调整。
- **模块必要性**：作者已有多项消融实现，并计划完成全部统一口径实验。当前判断是注意力全局池化和自回归解码最关键，GAT 的增益可能相对较小；在主方法训练和统计比较结束前，这些只能作为待检验假设。

# 第二章 Related Work

## 1. 本章功能

Related Work 不负责再次完整介绍本文方法，而要建立一条可以被审稿人核查的文献论证链：现有研究分别触及 APAL 的装配线组织、学习型序贯决策、多技能资源分配和扰动重调度，但这些研究通常在不同问题设定中处理其中一部分困难。本文需要说明，为什么这些局部进展尚不能直接解决物理工位、工人团队和工序约束同时耦合的 APAL 决策，并据此界定 HGP-PPO 的准确位置。

本章应完成六项任务：

1. 将 APAL 放入复杂装配线平衡与调度的研究谱系中，同时明确它不是普通 FJSP 的重新命名；
2. 总结优先规则、关键路径、构造式搜索和元启发式等传统求解范式，为 SPT、CPM、IG、SA 和 Beam 等实验基线建立文献依据；
3. 总结图表示学习和深度强化学习如何推动组合调度，但区分“加工顺序或工序—机器选择”与本文的多资源联合动作；
4. 讨论多技能工人、双资源约束和团队构造研究，说明单工人或固定工人类型模型与“需求人数由工序给定、成员身份由策略选择”的集合动作之间的差异；
5. 讨论动态、随机与鲁棒重调度研究，为后文的冻结任务一致性、稳定性和可行性评价提供依据；
6. 用统一比较维度定位最接近的 APAL 工作，形成克制、可证伪的研究缺口，而不是宣称“此前无人研究”。

## 2. 本章暂定核心论点

> 现有 APAL 与飞机总装研究已经考虑工序、空间、工人技能和人员分配，最新工作也已开始采用 GIN-PPO 等图强化学习方法。因此，本文的缺口不能笼统写成“尚无多资源调度”。更准确的核心缺口是：已有研究常将工序—工位划分或工人—站位配置预先给定、在单一工位内调度，或将人员分配作为独立阶段；然而在初始排程形成前，各站位最终承担的任务量和技能需求尚未确定。本文研究一种排程内生的联合配置机制：工人初始未绑定，策略显式选择工序和可行物理站位，再选择具体工人；工人首次被选中后永久绑定到该站位，使各站位人员规模与技能构成由逐步出现的任务需求决定，同时排除后续跨站流动。围绕该问题缺口，本文进一步研究高阶可行动作的结构化解码和单策略跨规模性能迁移。

该表述仍是需要系统检索和实验共同支持的工作假设。问题缺口的限定词必须保留为“决策时”“实体显式”“物理站位”“具体工人集合”和“统一策略”。本文暂不声称只调工序顺序或只做工序—站位决策必然不足；该判断需要分层动作对比实验支持。

## 3. 推荐章节结构

### 2.1 Complex assembly line research and APAL positioning

**目的**：先从问题结构而非算法出发，回答 APAL 与传统装配线平衡、装配线调度和飞机装配资源分配之间是什么关系。

**本节收束句的逻辑**：现有 APAL 文献并非没有考虑工人或多资源；区别在于很多工作将工位划分、站内调度和人员分配分阶段处理。本文要检验的是，在任务负荷与技能需求尚未确定时，让工人—站位绑定随排程首次分配逐步形成，并把跨工位工序选择、物理站位和具体工人集合放入同一个决策时序，是否能够改善资源均衡与排程质量。Ai et al. 仅作为这一研究路线的简短前序说明。

### 2.2 Traditional rules, search, and metaheuristics for scheduling

**目的**：为本文已有的 SPT、CPM、IG、SA 和 Beam 基线建立方法谱系，并说明传统方法为什么仍是评价学习型 APAL 调度器不可缺少的参照。

**计划内容**：

1. 区分优先调度规则、关键路径方法、构造式/有限宽搜索和元启发式，避免把所有非学习方法统称为“传统算法”；
2. 将 SPT 归入局部优先规则，将 CPM 归入 precedence/critical-path 导向方法，将 Beam 归入受限宽度的构造式搜索，将 IG 和 SA 归入迭代改进与元启发式；
3. 比较这些方法的状态信息、动作粒度、计算预算和是否显式处理工位与工人团队，确保实验中比较的是完整排程器而不是名称相同但约束不一致的简化版本；
4. 说明规则方法通常推理快、可解释，元启发式通常具有较强实例内搜索能力，但其性能和时间会受到邻域、终止条件与实例规模影响；
5. 预先统一公平性要求：相同 APAL 可行性检查器、相同目标函数、明确时间预算，并分别报告解质量、可行率和运行时间。

**候选证据**：APAL/复杂装配线中使用 dispatching rules、critical-path scheduling、iterated greedy、simulated annealing 和 beam search 的原始研究；不能只引用算法教科书来证明其在 APAL 上的有效性。当前这一部分文献覆盖较薄，需要与 APAL 直接文献一起补检。

**本节收束句的逻辑**：传统方法提供了速度、可解释性和实例内优化能力的强基线，但它们如何编码工序—站位—团队的联合状态与动作，必须在统一 APAL 约束下具体比较。

### 2.3 Learning-based scheduling and graph reinforcement learning

**目的**：说明图神经网络和强化学习为什么适合表达组合调度状态，同时限定这些方法可以自然迁移到 APAL 的部分与不能直接迁移的部分。

**计划内容**：

1. 综述 GNN 在组合优化中的关系归纳偏置，以及调度问题中析取图、二部图或异构图的常见状态表示；
2. 讨论 learned dispatching、Actor-Critic/PPO 和图策略网络如何替代手工优先规则完成序贯决策；
3. 比较典型方法的动作空间：选择下一工序、工序—机器对、规则或局部调整，与本文 operation—station—worker-team 联合动作并不等价；
4. 将 2026 年 APAL GIN-PPO 作为当前最接近的外部学习方法：其研究对象是单工位内的脉动装配调度，主要使用工序依赖图并通过 Serial SGS 完成资源调度；本文需要比较其资源实体表达、动作语义和跨规模训练协议；
5. 讨论已有方法的跨规模训练和推理设置，明确“图模型可接受可变规模输入”不自动等于“同一策略在大幅跨规模的未见 APAL 实例上保持性能”；
6. 把异构图、全局上下文聚合和 Pointer 解码分别作为后文方法动机，但此处不提前宣称某一具体模块优于所有替代方案。

**跨规模主张产生的后续写作义务**：方法章必须逐项解释实际实现中哪些机制避免固定规模依赖，例如共享节点/边参数、规模不变的全局聚合、与固定动作表解耦的顺序解码、动态可行性掩码，以及 400--800 工序随机规模训练分布。上述机制必须先与代码核对；实验章再用单 checkpoint、无微调、跨 283/680/2338/3182 实例的协议验证。Related Work 只提出“输入兼容性不等于性能泛化”的区别，不在这里提前证明泛化来源。

**候选证据**：Cappart et al.；Zhang et al.；Park et al.；Wang et al.；Xiao et al.；2026 年 APAL GIN-PPO。全文核验已确认后者使用同一模型从 30/50/100 工序训练规模迁移到 300/800 工序测试，因此本文不能把“同模型跨规模”本身写成首次贡献；差异应落在更大跨度、实体显式联合动作、硬约束合格率和推理成本。

**本节收束句的逻辑**：学习型图调度已经进入 APAL 直接研究，本文的差异不能再建立在“首次将 GNN/PPO 用于 APAL”上，而应落到多类型资源实体的显式状态表示、跨工位联合动作和具体工人集合的条件解码。

### 2.4 Heterogeneous resources, skilled workers, and team formation

**目的**：把本文最关键的资源耦合困难放到已有多技能工人、双资源调度和人员分配研究中讨论，解释为什么“增加工人特征”不等于“解决工人团队联合调度”。

**计划内容**：

1. 总结机器/站位与工人双资源约束、多技能工人匹配、工人可用性和人员负载等常见建模方式；
2. 区分 worker type、单工人指派、给定人数的工人集合选择和由策略自主决定团队人数四种动作语义；
3. 说明 APAL 中相同技能工人的局部近似同质性：个体差异可能弱于工序或站位差异，但具体工人的可用性、冲突和团队组成仍影响可行性；
4. 将 Skill Hub 定位为对 worker—skill—operation 语义关系的显式分解和稀疏聚合机制，而不是把虚拟节点本身写成已被证明的新颖性；
5. 讨论团队已选成员如何影响后续工人选择，为自回归团队历史条件化建立文献与问题动机；同时明确当前实现中的团队需求人数 $q_i$ 由工序预先给定，策略只选择恰好 $q_i$ 名具体工人，不学习停止时机或团队长度。
6. 单独讨论 ex-ante worker–station assignment 与 schedule-endogenous worker–station binding：后者不是增加一个工人选择站位的动作，而是在站位确定后，由该站位当前承载的工序和技能需求限定候选工人；未绑定工人一旦被选中即永久锁定到该站位，不允许后续跨站移动。

**候选证据**：Liu et al. 的 AFAL 多技能工人调度、Wen et al. 的 APAL 熟练工分配 QLPSO、Fang et al. 的飞机总装动态工人分配，以及本地 CAC 稿件中的 Wang、Zhao、Hu、Zhong、Yi 等多技能/双资源候选工作。Wu 和 Merchant 等非调度图学习工作最多作为结构设计启发，不宜占据核心 Related Work 篇幅。

**本节收束句的逻辑**：已有 APAL/AFAL 研究已经处理多技能人员与多人协作，本文不能把“考虑工人”本身作为缺口。更具体的差异是：在工序所需人数给定时，由学习策略结合已选工序、站位可行域和团队历史，顺序构造具体工人子集，而不是由固定优先规则或独立后处理过程完成人员分配。

### 2.5 Dynamic, stochastic, and stability-aware rescheduling

**目的**：为本文次级研究问题提供独立的理论位置，避免把动态重调度仅写成初始调度方法的附加演示。

**计划内容**：

1. 区分静态调度、滚动重调度、事件驱动重调度、随机调度与鲁棒调度；
2. 归纳机器/站位不可用、工人缺勤、处理时间变化和紧急任务等典型扰动；
3. 讨论重调度不能只优化新 makespan，还要评价原计划偏离、冻结任务一致性、硬约束可行性和响应时间；
4. 比较从头求解、局部修复、规则/元启发式和学习型重调度策略；
5. 准确限定本文主张：复用主要架构并通过 warm start 和重调度训练完成任务适配，不声称初始调度 checkpoint 对扰动场景零样本通用。

**候选证据**：Smit et al.；Xiao et al.；Tereshchuk et al.，以及本地总结中的动态 JSSP/重调度研究。需要补充 APAL 或复杂装配系统中的稳定性研究。

**本节收束句的逻辑**：现有动态调度工作提供了扰动处理与稳定性评价基础，但 APAL 的冻结任务、站位空间和人员团队约束要求在统一可行性语义下进行局部重构。

### 方法审计后的贡献层级

1. **可以作为研究缺口**：G1 排程内生、需求驱动且一次形成的工人—站位绑定与实体显式多资源联合决策；G2 与联合状态匹配的高阶约束动作解码。
2. **作为验证贡献而非研究缺口**：E3 单策略跨规模性能迁移。Wen et al. (2026) 已训练一个 GIN-PPO 模型并从 30/50/100 工序迁移到 300/800 工序测试；本文的增量只能落在更大规模跨度、实体显式联合动作、硬约束合格率和推理效率的共同验证上。
3. **作为支撑机制而非独立缺口**：Skill Hub 用于技能关系语义分解和边稀疏化；实体级注意力池化用于形成规模无关的全局瓶颈上下文；事件驱动 MDP 用于连续时间下的可行排程构造；独立 Actor/Critic 编码器用于减少价值梯度干扰。
4. **作为次级扩展而非核心新颖性**：在相同主要状态—动作结构上 warm start 并训练动态重调度任务，同时评价冻结任务、takt、站位变化和团队变化。
5. Skill Hub、注意力池化和独立 Critic 只有在相应消融、效率或稳定性数据显著时才能上升为方法贡献，不能仅凭实现存在就转化为文献缺口。

### 实现与论文措辞审计

1. 当前 `ppo_agent.py` 按工序特征读取预定需求人数，并循环选择直到达到 $q_i$；`WorkerPointer.forward_stop()` 在当前主动作路径中未被调用。因此全文将 `variable-length worker team` 改为“operation-dependent team cardinality”或“a worker subset of prescribed cardinality”，不得声称策略自主学习团队长度。
2. 当前工人 Pointer 的学习打分输入包括工序嵌入、候选工人嵌入和已选团队均值，但不直接包括所选站位嵌入；所选站位主要通过 station-binding compatibility 改变可行候选集，技能约束由所选工序决定。默认配置允许选择当前正忙但未来会释放的兼容工人，并通过最早开工时间保持时间互斥；只有启用 queue mask 时才按等待时长额外过滤。初始 `worker_locks=0`，工人首次被站位选中后写入永久锁，后续不能进入其他站位。因此系统语义是 schedule-endogenous binding，网络语义是 station-conditioned feasible-set selection；不能写成工人跨站移动，也不能声称打分器直接学习完整的 station–worker compatibility。
3. 注意力全局上下文由 task、station、worker 三类实体分别聚合后拼接，并用于任务 Pointer 与 Critic；Skill 节点当前未直接进入全局池化。方法章应按实际数据流描述，避免写成四类节点全部参与全局池化。
4. 当前主训练目录包含 80 个约 436--795 工序实例。283/680/2338/3182 通过 `multi_benchmark_eval` 参与验证，并可能参与 best checkpoint 选择，因此当前只能称跨规模 validation。`multiscale_initial_schedule.yaml` 中 200--3100 训练目录当前不存在，不能作为已执行协议。若要使用 held-out/zero-shot test 表述，最终运行必须取消四基准的 checkpoint selection 角色。

### 分层动作主张的实验门槛

当前不能仅凭组合规模分析断言低阶动作一定无法取得足够好的排程。实验章应尽量建立以下递进比较：

1. **Sequence-only baseline**：策略只选择工序，站位与工人团队由同一个确定性可行分配器补全；
2. **Operation–station baseline**：策略联合选择工序和站位，工人团队由同一个确定性或受控启发式分配器补全；
3. **Full joint policy**：策略按条件顺序构造工序、站位和给定需求人数的具体工人集合；
4. 三类方法必须共享目标函数、约束检查器和可比计算预算，并报告 makespan、可行率、推理时间及失败类型；
5. 如果前两类基线暂时无法实现，论文只能说本文“直接建模”多资源联合决策，不能说低阶决策“无法处理”或“必然较差”。

### 排程内生工人—站位绑定的实验门槛

要把 schedule-endogenous binding 从建模特点提升为创新贡献，至少需要以下对照与指标：

1. **Ex-ante static binding**：在排程前按人数和技能覆盖规则把工人固定到各站位，之后所有方法只能在所属站位内选人；
2. **Two-stage binding**：先确定工序—站位方案，再依据各站位汇总任务量与技能需求分配工人，最后完成站内排程；
3. **Schedule-endogenous binding**：工人初始未绑定，首次被某站位选中后永久绑定，绑定与工序—站位排程共同形成；
4. 三组共享总工人数、技能矩阵、工序需求、可行性检查器和计算预算；若 two-stage 使用完整任务分配信息，应明确它是带额外信息的强基线；
5. 除 makespan、feasible/eligible rate 和运行时间外，报告站位劳动负荷变异系数、各站位技能覆盖/短缺次数、工人利用率及因绑定导致的候选集枯竭或 deadlock 次数；
6. 当前绑定一旦形成便不再改变，因此不需要报告跨站移动次数，但必须明确其与允许人员转移的动态 workforce allocation 问题不同。

## 6. 写作边界与风险控制

1. 不使用“现有方法无法处理”这种绝对表述，改为指出其原始问题定义、动作粒度或实验协议未覆盖本文条件；
2. 不用普通 FJSP 文献直接证明 APAL 新颖性，FJSP 只承担方法来源或相邻资源调度对照；
3. 不把所有异构图应用都列入正文，只保留能解释调度关系建模、技能聚合或动作解码的直接证据；
4. 不因虚拟 Skill Hub 节点命名新颖就宣称方法新颖，贡献必须落到关系表达、计算规模或调度性能的可检验证据；
5. 不把“网络可以接收任意节点数”本身当作跨规模泛化证据；本文可依据同一 checkpoint、无梯度微调的跨实例评价主张跨实例规模泛化，但必须同时披露训练拓扑来源、模型选择角色和测试边界。只有完全隔离模型选择的实例才进一步称为 held-out test；
6. 不在分层动作实验完成前声称只排工序顺序或只做工序—站位决策不足；
7. 明确 Ai et al. 是同一课题组的前序工作，不能将继承的 APAL 建模思想包装为本文首次提出；
8. Ai et al. 只需简短披露继承关系，不占用核心比较篇幅；主要外部比较对象转为 APAL GIN-PPO、QLPSO 和 AFAL 多技能工人调度；

# 第三章 Problem Formulation and MDP Modeling

## 1. 本章功能

第三章负责把前两章提出的工业困难和研究缺口转化为可复现、可检验的形式化问题。读者在本章结束时应能明确回答：

1. 本文调度的实体、输入和输出分别是什么；
2. 工序、站位、工人和时间之间存在哪些硬约束；
3. 工人如何在排程中形成一次性的永久站位绑定；
4. 为什么一个动作必须同时包含工序、站位和给定人数的具体工人集合；
5. 连续时间排程如何被转化为有限长度的事件驱动 MDP；
6. 初始排程模型如何扩展到物料扰动导致的工序开始延误重调度。

本章只定义问题、目标、约束和 MDP，不展开 HB-GAT-PN 的消息传递、池化、Pointer 打分或 PPO 更新公式。这些内容留到第四章 Proposed Method。

## 2. 本章核心论点

APAL 初始排程可形式化为一个连续时间、多资源联合调度问题：在满足工艺前序、脉动线空间单调性、固定站位、站位并发容量、工人技能、给定团队人数、工人互斥和永久站位绑定的条件下，为每个物理工序联合确定站位、具体工人集合及起止时间。工人初始未绑定，其首次被某站位上的工序选择后即永久绑定到该站位，因此人员配置不是独立的排程前输入，而是工序—站位—工人联合排程的内生结果。该问题随后被转化为事件驱动 MDP；动态重调度在继承基准排程、冻结已开始工序和加入任务释放延迟的基础上，进一步考虑解质量与排程稳定性。

### 3.2 Initial APAL scheduling formulation

#### 3.2.1 Processing-time model

当前实现中的实际加工时间写为：

$$
D_i(W_i)=
\frac{p_i^{\mathrm{std}}q_i}
{\rho^{q_i-1}\sum_{w\in W_i}\eta_w},
\qquad |W_i|=q_i,\qquad \rho=0.95.
$$

其中，$p_i^{\mathrm{std}}$ 是工序 $i$ 在额定团队人数 $q_i$ 下的基础标准持续时间，$W_i$ 是具体工人集合，$\eta_w$ 是基础效率。$\rho=0.95$ 为固定经验参数，不将其表述为经工厂数据标定的物理规律。

#### 3.2.2 Makespan objective, takt time, and reward shaping

作者已确认初始排程的唯一工程优化目标是最小化 makespan：

```text
min C_max = max_{i in O+} C_i.
```

令站位 $m$ 上全部工序的最晚完成时刻为 $C_m^{end}$，则本文代码中的 makespan 同时等于真实物理站位中最大的站位完工时间：

```text
T_takt = max_{m in M} C_m^end = C_max.
```

在真实工厂的五站位 APAL 中，若生产线按固定节拍脉动、飞机每经过一个节拍前进一个站位，则单架飞机依次经过全部站位的线内流动时间为：

```text
T_aircraft = |M| T_takt = 5 C_max.
```

因此，最小化代码中的 $C_{\max}$ 等价于最小化脉动节拍，并按固定比例缩短单架飞机通过五个站位的线内流动时间。正式英文必须区分 `takt time / cycle time` 与 `aircraft flow time`，不能继续沿用旧稿中 $C_{\max}=5\times\text{Cycle Time}$ 的符号，因为旧式把被优化的站位最大完工时间和五站位总流动时间都记成了 $C_{\max}$。

站位劳动负荷标准差只作为训练时的辅助 reward shaping，帮助策略减少局部负载失衡，不改变正式优化目标。MDP 小节需如实披露该训练技巧，但不把本文定义为显式双目标优化；实验主表以 makespan 为首要指标，负荷均衡作为诊断指标。

#### 3.2.3 Assignment, temporal constraints, and schedule-endogenous worker–station binding

正式模型计划包含以下约束组：

1. **唯一站位分配**：每个物理工序恰好从五个物理站位中选择一个；工厂不预先指定工序所属站位；
2. **时间前序**：若 $(i,j)\in\mathcal{E}^{+}$，则 $B_j\ge C_i$；
3. **脉动线空间单调性**：若 $(i,j)\in\mathcal{E}^{+}$，则 $m_j\ge m_i$。非严格不等式允许前后序工序位于同一站位，但不允许后继返回上游站位；
4. **加工时间一致性**：$C_i=B_i+D_i(W_i)$；
5. **团队人数与唯一成员**：$\sum_w y_{iw}=q_i$，且同一工人不能在同一团队中重复出现；
6. **技能匹配**：$y_{iw}\le H_{w,k_i}$；
7. **工人时间互斥**：同一工人的正工时任务区间不得重叠；
8. **站位槽位容量**：任意时刻站位 $m$ 上的并发工序数不超过 $c_m$；
9. **内生工人—站位绑定**：工人首次被站位选中后，其绑定在同一实例及后续重调度中保持不变；未绑定工人仍可被任一合法站位首次选择；
10. **完整性**：所有物理工序均被调度，虚拟节点只继承和传播工艺约束。

策略只输出 $(i,m_i,W_i)$。前向分配引擎以当前决策时刻、物料释放时刻、紧前工序完成时刻和团队可用时刻的最大值作为开工下界，再通过站位容量扫描确定最早可行的 $B_i$，并令 $C_i=B_i+D_i(W_i)$。

为避免在正文中引入庞大的离散时间索引，工人互斥和站位容量优先使用区间指示函数或 cumulative/resource-capacity 表达；若目标期刊要求标准 MILP，再在附录给出时间索引或析取变量形式。

该小节是第三章最关键的新增内容，不能继续沿用旧稿中静态参数 $\mathit{Loc}_w$ 的模糊写法。

**完整排程层面的等价约束**：

```text
sum_m z_wm <= 1,                                      for each worker w
y_iw + x_im <= 1 + z_wm,                              for each i,w,m
```

第一式保证每名实际使用的工人至多绑定一个站位，第二式保证若工人 $w$ 被分配给位于站位 $m$ 的工序，则其绑定变量必须为 $z_{wm}=1$。这组约束描述最终排程中的永久绑定结果。

**序贯决策层面的状态转移**：令 $\ell_w^{(t)}\in\{0,1,\ldots,M\}$ 表示决策步 $t$ 前工人的绑定状态，0 表示未绑定。若动作在站位 $m_t$ 选择工人 $w$，则：

```text
ell_w^(t+1) = m_t,       if ell_w^(t)=0 and w is selected;
ell_w^(t+1) = ell_w^(t), otherwise.
```

候选工人必须满足 $\ell_w^{(t)}\in\{0,m_t\}$。因此“首次选择形成绑定”是 MDP 状态转移，不是一个独立的工人选站动作。完整排程模型中的 $z_{wm}$ 与序贯模型中的 $\ell_w^{(t)}$ 分别承担最终结果和生成过程的表达，两者不能混用。

### 3.3 Material-disruption-induced operation-start delay rescheduling

动态重调度作为初始模型上的次级问题扩展，应先定义其新增输入、冻结约束和评价目标，再在下一节给出初始排程与重调度共用的事件驱动 MDP。这样保持“两个优化问题定义在前、统一序贯表达在后”的顺序，但不把两者混成同一个优化目标。

**计划内容**：

1. 输入一个合法基准排程 $\pi^0$、重调度时刻 $\tau^r$，以及物料扰动影响的工序及其更新后最早释放时刻 $r_i$。正式 R5 协议满足

   $$
   \mathcal{O}^{\mathrm{frz}}=\{k\in\mathcal{O}^{+}\mid B_k^0\le \tau^r\},\qquad
   \mathcal{O}^{\mathrm{mov}}=\{i\in\mathcal{O}^{+}\mid B_i^0>\tau^r\},
   $$

   $$
   \varnothing\ne\mathcal{O}^{\mathrm{del}}\subseteq\mathcal{O}^{\mathrm{mov}},\qquad
   r_i=
   \begin{cases}
   B_i^0+\Delta_i, & i\in\mathcal{O}^{\mathrm{del}},\\
   0, & i\notin\mathcal{O}^{\mathrm{del}},
   \end{cases}
   \quad \Delta_i>0.
   $$

   因而任一可重排工序均须满足 $B_i\ge\max(\tau^r,r_i)$；
2. 基准排程中开始时间不晚于 $\tau^r$ 的工序被冻结，其原站位、团队和时间安排保持不变；
3. 尚未开始的工序可重新选择站位、团队和开始时间，但继续满足第三章定义的全部硬约束；
4. 基准排程中已形成的工人—站位绑定由冻结工序恢复，后续可移动工序不能破坏该永久绑定；
5. 目标同时考虑重调度后 makespan、站位负荷、相对基准节拍的超限、开始时间偏差、站位变化率和团队变化率；
6. 所有硬约束违规或未完整排程的方案不进入可比较解集合。

当前实现采用以下加权综合目标：

$$
\begin{aligned}
\min S={}&0.20\frac{C_{\max}^{r}}{T_{\mathrm{takt}}}
+0\frac{\sigma_L^r}{L_{\mathrm{ideal}}}
+3\frac{\max(0,C_{\max}^{r}-T_{\mathrm{takt}})}{T_{\mathrm{takt}}}\\
&+4\frac{\bar D_B^r}{T_{\mathrm{takt}}}
+4R_{\mathrm{sta}}^r
+0.3R_{\mathrm{team}}^r.
\end{aligned}
$$

其中，$\bar D_B^r$ 为可重排工序的平均绝对开工时间偏差，$R_{\mathrm{sta}}^r$ 为站位改变率，$R_{\mathrm{team}}^r$ 为具体工人集合改变率；团队比较忽略成员顺序。$\sigma_L^r$ 的权重为零，只报告为诊断指标，不影响方案选择。

正文必须同时报告各原始分项，不能只给一个加权总分。由于本研究当前只实现物料扰动导致的工序开始延误，第三章不应把模型泛化为已经覆盖设备故障、工人缺勤、加工时间变化或任意随机事件。

### 3.4 Unified event-driven MDP formulation

> 写作状态：中文初稿已完成。正文已明确两类任务共享状态—动作—事件转移骨架，但使用不同奖励与独立 checkpoint；重调度模型由初始 checkpoint warm-start 后继续训练。奖励的数值缩放与截断留至第五章实验设置。

#### 3.4.1 State and action

状态 $s_t$ 应概括当前未完成工序及其前序状态、已分配站位、工人技能与绑定、工人释放时间、站位负荷与槽位释放时间。重调度模式额外加入基准排程、冻结状态和受物料扰动影响的工序最早释放时刻 $r_i$。第三章只定义状态包含的信息；节点特征维数和异构图边类型留到第四章。

每个正工时工序对应一次联合指派动作：

```text
a_t = (i_t, m_t, W_t),   |W_t| = q_i.
```

零工时层级节点由环境自动穿透，不产生站位或工人动作。因此 episode 的资源决策步数应表述为物理工序数 $|\mathcal{O}^{+}|$，不能继续写成包含全部虚拟节点的固定 $N$ 步。扁平动作集合的规模可写为：

```text
|A_flat(s_t)| = sum_{i in R_t} sum_{m in M_i(s_t)} |T_im(s_t)|,
```

其中 $R_t$ 为当前可调度工序，$M_i(s_t)$ 为合法站位集合，$T_{im}(s_t)$ 为满足技能、绑定和给定人数约束的工人集合族。若候选人数为 $h_{im}$，仅考虑给定人数选择时已有 $\binom{h_{im}}{q_i}$ 个候选团队。

#### 3.4.2 Feasible action set, transition, and reward

掩码规则按动作层次分别定义：

1. 工序掩码：前序未完成、释放时间未到达或不存在任何可行站位—团队组合；
2. 站位掩码：违反物理前序站位范围、当前槽位容量或可兼容工人数不足；当前研究中的物理工序不预先固定站位；
3. 工人掩码：技能不匹配、已永久绑定到其他站位、已在当前团队中选择；可选 queue mask 仅在启用时过滤等待时间过长的工人。

需要准确说明：当前默认配置并不把所有正忙工人直接判为非法。工人释放时间进入最早开工时间计算，从而保证任务区间不重叠；只有启用 queue mask 时，等待过长的工人才会在解码阶段被额外过滤。

选择动作后，环境根据当前时间、前驱完成时间、团队中最晚工人释放时间和站位槽位可用时间计算最早可行开始时间，再生成完成事件。若当前仍存在可行动作，控制权立即返回策略；只有不存在可行动作时，物理时钟才跳到最近的资源释放、任务完成或物料到达事件。因此不能笼统写成“每执行一个动作，时间都跳到下一个完成事件”。

初始排程奖励按实际代码定义为归一化预估完工时间增量与站位劳动负荷标准差增量的加权负值；第三章给出结构公式，数值缩放和截断放在第五章实验设置中披露：

```text
r_t = -alpha Delta C_est,t / C_ref
      -beta Delta sigma(L_t) / L_ref.
```

其中 $C_{\mathrm{est},t}$ 是部分排程的完工时间估计；负荷项仅用于奖励塑形，正式优化目标仍是最小化 makespan。重调度使用上一节综合目标的增量奖励，并同时报告 makespan 与稳定性原始分项。正式公式需要与最终实验配置逐项核对。

**Transition to the proposed method.**

本节用一段总结问题为什么需要第四章的方法，但不提前宣称方法有效：

1. 状态由不同语义的实体和关系组成；
2. 工人绑定使早期人员选择改变后续站位的技能供给，决策具有长期不可逆性；
3. 给定人数的团队选择产生组合增长，且候选集合随工序、站位和历史选择改变；
4. 连续时间资源约束要求每一步都维护可行性，而不能只在完整排程生成后修复；
5. 因此第四章将分别说明异构图状态表示、全局上下文聚合、自回归联合动作构造和自适应掩码。

# 第四章 Proposed Method: HGP-PPO

## 1. 本章功能

第四章回答的核心问题不是“模型由哪些神经网络模块组成”，而是：**HGP-PPO 如何把第三章定义的 APAL 异构状态、组合联合动作和动态硬约束，转化为可训练、可变规模且逐步保持可行性的策略。**

本章需要完成五项任务：

1. 给出从异构图观测到联合动作和状态转移的完整数据流；
2. 说明 operation、station、worker 和 skill 四类节点及其关系为何与 APAL 约束逐项对应；
3. 说明全局上下文池化和自回归 Pointer 如何避免固定维输出头，并降低直接枚举工人组合的负担；
4. 说明动态掩码如何把前序、空间、技能、容量和排程内生绑定约束嵌入每个解码子步；
5. 说明相同表示与解码骨架如何支持跨规模输入，并通过输入扩展和 warm start 适配物料扰动下的工序开始延误重调度。

本章不承担以下任务：

- 不在方法章宣称跨规模泛化已经成立；该结论必须由第五章的严格训练—验证隔离实验支持；
- 不把模块复杂度本身当作创新证据；GAT、池化、Pointer、Skill Hub 和 mask 均需对应消融或效率证据；
- 不重复第三章的完整约束推导，只说明这些约束在图、特征、掩码和环境校验器中的实现位置。

## 2. 本章核心论点

第四章拟建立如下机制链：

> APAL 状态包含具有不同语义和动态尺度的工序、工位、工人及技能关系；关系特定的异构图注意力用于传播这些局部依赖，按节点类型归一化的注意力池化形成与节点数量无关的全局上下文。策略随后依次选择工序、工位和给定人数的具体工人集合，并在每一子步更新可行性掩码。该分解不消除 APAL 的组合复杂性，但避免显式枚举所有工序—工位—工人集合，使策略能够在可变节点规模上复用同一组参数。

该核心论点对应四层必要性：

1. **表示必要性**：扁平向量难以保留 precedence、assignment、skill possession 和 skill requirement 等不同关系语义；
2. **全局感知必要性**：仅依靠局部消息传递不足以直接暴露跨工位负荷竞争、稀缺技能供给和未绑定工人分布；
3. **解码必要性**：联合动作包含一个无序工人集合，直接扁平化需要处理随状态变化的组合候选族；
4. **约束必要性**：排程内生绑定使早期工人选择不可逆地改变后续可行集，不能仅在生成完整排程后修复。

### 4.2 Heterogeneous graph representation and global encoding

**Relation types and dynamic graph update.**

正文建议用一张关系表准确对应代码：

| 关系 | 方向 | 静态/动态 | 语义 |
|---|---|---|---|
| precedes | Operation $\rightarrow$ Operation | 静态 | 工艺前序 |
| assigned-to | Operation $\rightarrow$ Station | 动态 | 已排工序的站位归属 |
| has-task | Station $\rightarrow$ Operation | 动态 | 上述关系的反向消息 |
| done-by | Operation $\rightarrow$ Worker | 动态 | 已排工序的团队成员 |
| has-skill | Worker $\rightarrow$ Skill | 工人采样后固定 | 工人能力 |
| required-by | Skill $\rightarrow$ Operation | 静态 | 工序需求技能 |
| requires | Operation $\rightarrow$ Skill | 静态 | 技能需求的反向消息 |
| provided-by | Skill $\rightarrow$ Worker | 工人采样后固定 | 工人能力的反向消息 |

必须明确两个“不在图边中”的约束：

1. 工序—工位可行区间当前由 station mask 表达，不存在静态 operation-feasible-at-station 边；
2. 工人—工位永久绑定当前由 worker 节点特征、`worker_locks` 状态转移和 worker mask 表达，不存在显式 worker-station 边。

因此不能继续写“图边已经直接编码全部站位兼容性和工人—站位关系”。更准确的说法是：**图表示负责关系状态，掩码负责动作可行域，两者共同表达 APAL 约束。**

**Skill Hub as semantic factorization.**

Skill Hub 的首先是语义作用：把“工人拥有什么技能”和“工序需要什么技能”分解为两类关系，使相同技能工人共享技能层信息。其潜在稀疏化作用应通过边数公式和实验表达，而不能预设一定成立。

令 $H_{wk}$ 表示工人 $w$ 是否具有技能 $k$，$k_i$ 为工序 $i$ 的需求技能。直接 Worker-to-Operation 技能边数量为：

```text
E_direct = sum_i sum_w H_(w,k_i).
```

单向 Skill Hub 边数量为：

```text
E_hub_forward = sum_w sum_k H_wk + |O|.
```

当前完整模型使用双向 Skill Hub，因此对应：

```text
E_hub_bidir = 2 (sum_w sum_k H_wk + |O|).
```

是否减少边数取决于技能分布、工序规模和是否加入反向边。由于当前 direct 版本只有 Worker $\rightarrow$ Operation，而双向 Hub 还引入 Operation $\rightarrow$ Skill $\rightarrow$ Worker 信息，二者不是严格语义等价的纯稀疏化对照；现阶段只描述当前双向 Skill Hub 的关系建模机制，不预先承诺新增变体实验，也不宣称其必然带来计算或排程性能优势。

**Relation-aware heterogeneous graph attention encoder.**

本节按“动机—机制—证据接口”写作。

**动机**：同一个节点可能同时接收前序、资源归属和技能供给消息，不同关系不应共用完全相同的变换。

**机制**：四类原始特征先由类型特定 MLP 投影到统一隐空间。每层对每种关系使用独立 GATv2 卷积，在关系内部归一化邻居注意力，再对到达同一节点类型的关系输出求和，并使用 LeakyReLU 和残差连接更新表示。可写为：

```text
m_i^(r,l) = sum_(j in N_i^r) alpha_ij^(r,l) W_r^(l) h_j^(l-1),
h_i^l = h_i^(l-1) + sigma(sum_r m_i^(r,l)).
```

当前主配置为 5 层、4 个注意力头、隐藏维 128；这些值放入 Implementation Details，不作为方法创新。

**证据接口**：`w/o GAT` 只能支持“关系消息传递有贡献”，不能证明 GATv2 必然优于所有 GNN。若要声称注意力本身必要，还需与参数量接近的 relation-aware GraphSAGE/GCN 或其他聚合器比较。

实现上，Actor 与 Critic 默认使用独立的输入嵌入器、异构图编码器和全局池化参数。该设置仅在 4.4 的 PPO 实现细节中简要披露，不作为方法贡献。

**Type-wise attention global context pooling.**

当前完整模型不是简单平均池化，而是分别对 Station、Operation 和 Worker 节点计算学习式注意力权重：

```text
alpha_v^X = softmax_{u in V_X}(a_X(h_u)),
g_X = sum_{v in V_X} alpha_v^X h_v,
g = [g_station || g_operation || g_worker].
```

其中 Station 使用独立注意力网络，Operation 与 Worker 在当前实现中共享一个注意力网络；Skill 节点只通过图消息影响实体嵌入，不直接拼接到 $g$。这一细节需要在图和公式中一致。

该模块的两个作用分别是：

1. 将可变数量节点压缩为固定维全局向量，为 Task Pointer 和 Critic 提供跨实体竞争状态；
2. 允许模型相对突出瓶颈工位、关键工序或稀缺工人，而不是对所有节点等权平均。

`w/o attention pooling` 的当前实现使用每类节点的 mean 与 max 拼接，而不是单独的 mean pooling。因此消融名称应写成“attention pooling vs mean+max pooling”，不能写成“去掉池化”。建议补充注意力权重可视化或瓶颈相关性分析，防止仅凭 makespan 反推其解释性。

### 4.3 Autoregressive constrained joint decoder

> **写作状态：中文初稿已完成。** 正文已按正式 full_x 配置修正为显式 station-conditioned、pressure-aware Worker Pointer，并删除“计划加入站位嵌入”的过时表述。

**Joint-action factorization.**

对给定工序需求人数 $q_i$，最终计划采用的策略概率分解为：

```text
pi(a_t|s_t)
= pi_O(i_t|s_t)
  pi_M(m_t|i_t,s_t)
  product_(r=1)^(q_i) pi_W(w_t^r | i_t, m_t, W_t^(<r), s_t).
```

正式 full_x 配置中，所选站位 $m_t$ 既通过工人可行集影响候选范围，其节点嵌入也显式进入 Worker Pointer 的查询向量。正文据此描述当前已实现架构，不再保留 `[planned]` 标记。

**Operation pointer.**

Task Pointer 结合全局上下文 $g$ 与每个候选工序嵌入产生 logit，经 task mask 后形成可调度工序上的分类分布。该头的输出长度随当前图中的工序节点数变化，不依赖预设最大工序数。

**Station selector.**

Station Selector 以所选工序嵌入作为 query，以各工位嵌入作为候选 key，计算工序—工位兼容得分；task-specific station mask 排除违反空间单调性、固定工位、槽位容量或兼容工人数约束的工位。

**Prescribed-cardinality worker-team construction.**

Worker Pointer 顺序选择恰好 $q_i$ 名工人。正式 full_x 配置的第 $r$ 步 query 综合所选工序、所选站位、全局上下文、sum-mean-max 团队表示、技能压力、技能占用、选择进度和团队运行状态；候选 key 综合工人嵌入、压力暴露、动态最早完工特征、额外技能边际稀缺度和下一前沿压力。打分采用基础 pointer 与 query-candidate 交互残差之和。

每选一人即更新团队集合表示、技能占用、等待与效率汇总并掩码该工人，直到达到给定人数。显式 station embedding 使两个具有相同可行工人集合、但负荷与已绑定资源状态不同的工位能够产生不同的工人排序。

必须保留三项边界：

1. 当前主路径不调用 STOP head，策略不自主决定团队长度；
2. Pointer 不消除组合复杂性，而是把显式枚举 $\binom{h_{im}}{q_i}$ 个团队改为 $q_i$ 次候选工人评分；解码开销近似为 $O(|\mathcal{R}_t|+|\mathcal{M}|+q_i|\mathcal{W}|)$，不含图编码；
3. 最终动作中的团队是无序集合，但实现优化的是一次有序生成路径的 log-probability，并未对同一集合的全部排列概率求和。该实现选择应在可复现性说明或局限性中披露。

各增强状态是否带来独立性能收益必须由对应消融支持；方法章只描述当前完整模型，不根据结构设计预判模块必要性。

**Adaptive feasibility masks and endogenous binding update.**

本节应与第三章的三层可行集一一对应：

- **Task mask**：排除未 ready、物料释放时间未到或不存在任一可行工位—团队组合的工序；
- **Station mask**：排除违反固定工位、前序诱导最小工位、最大允许工位、当前槽位容量或技能兼容工人数不足的工位；
- **Worker mask**：排除技能不匹配、已绑定其他工位、已在当前团队中被选择的工人；可选 queue mask 仅在启用时排除等待过长工人。

工人首次被工位 $m_t$ 选中后，环境执行：

```text
ell_w^(t+1) = m_t,  if ell_w^t=0 and w in W_t;
ell_w^(t+1) = ell_w^t, otherwise.
```

后续 Worker mask 仅允许 $\ell_w\in\{0,m_t\}$。这使工人供给在不同工位间的分配由排程逐步内生形成，而不是排程前预分配，也不是工人后续在工位间持续移动。

忙碌工人在默认配置下仍可被指派给未来工序；其释放时间进入最早开始时间计算。论文需要区分“资源时间互斥”与“解码时直接屏蔽所有忙碌工人”。

掩码负责提前收缩动作域，环境约束引擎仍需在动作执行和最终排程导出时复核区间容量与完整性。因此，在所有验证实例达到严格 `valid=1` 之前，不写“mask 从数学上保证所有输出绝对可行”。

### 4.4 PPO learning and transfer

PPO 训练保留三类解码概率之和作为联合动作 log-probability：

```text
log pi(a_t|s_t)
= log pi_O + log pi_M + sum_(r=1)^(q_i) log pi_W^r.
```

该联合量用于行为重放一致性检查和联合 KL 监控；正式 `full_x` 并不使用单一联合概率比构造策略损失，而是对 task、station 和 worker-team 三个分量分别计算概率比、条件优势与裁剪 surrogate。

使用 GAE 估计优势：

```text
delta_t = r_t + gamma V(s_(t+1)) - V(s_t),
A_t = sum_(l>=0) (gamma lambda)^l delta_(t+l).
```

三个条件价值头分别使用 $s_t$、$(s_t,i_t)$ 和 $(s_t,i_t,m_t)$ 作为上下文。以同一 GAE return 减去行为采样时冻结的条件价值，在各分量有效样本内分别标准化后，得到三类条件优势。策略目标采用 active-component 平均的 factorized clipped surrogate：

```text
rho_t^x = exp(log pi_theta^x - log pi_old^x), x in {O,M,W};
L_policy = -E[mean_active_x min(rho_t^x A_t^x,
                 clip(rho_t^x,1-epsilon,1+epsilon) A_t^x)].
```

总损失由分解式策略损失、全局与条件裁剪 value loss 和分层归一化熵正则组成。当前实现分别计算 task、station 和 worker-team entropy，以各自合法候选数的对数归一化，从而减小候选维度差异造成的熵尺度偏置。训练工程细节如 AMP、梯度累积、梯度裁剪和向量环境放在 4.5 或实验设置，不与算法创新混写。

初始排程的负载标准差只出现在 reward shaping 中；PPO 真正服务的评价目标仍是 makespan 最小化。本节引用第三章奖励公式，不重新定义第二个正式优化目标。

Actor 与 Critic 默认使用独立的输入嵌入器、图编码器和全局池化参数，但这只是一个较小的训练稳定性配置，不作为独立创新点，也不再单列章节。正文在 PPO 实现细节中用一至两句说明即可；除非后续把该设置提升为贡献，否则无需为它单独增加消融实验。

**Transfer-oriented design: scale compatibility and rescheduling adaptation.**

跨规模兼容与重调度都体现同一表示—解码骨架的迁移能力，因此合并到一个主小节；但二者的证据含义不同，必须保留两个子小节：前者是未见图规模上的零微调泛化，后者是加入任务特征并继续训练后的跨任务适配。

**Scale-compatible representation and decoding.**

本节不是提前报告泛化结果，而是解释模型为何没有固定规模结构障碍：

1. GATv2 在节点与边上共享参数，可处理不同数量的工序和工人；
2. 按节点类型归一化的池化把可变节点集变为固定维上下文；
3. Pointer 对当前候选节点逐一打分，不使用与最大工序数或最大工人数绑定的固定分类头；
4. 工时、等待和负荷使用实例内生尺度与相对量归一化；
5. 训练实例的随机生成与属性扰动只在第五章实验协议说明，不与结构性质混写。

随后立即限定：这些机制提供 **size-compatible inductive bias**，但跨规模泛化仍需由实际性能证明。方法章本身只解释结构条件；训练范围、拓扑来源和锁定 checkpoint 的角色必须在实验章披露，以区分结构兼容、同一数据族内跨规模外推与完全隔离的跨数据集泛化。

**Adaptation to task-delay rescheduling.**

重调度保留四类图、GAT、池化和三层解码骨架，但并非“权重与输入完全不变”。当前实现包含：

1. 将 operation 输入从 18 维扩展到 24 维，加入基准开始时间偏移、基准工位、基准团队规模、冻结标志、延迟标志和逾期量；
2. 恢复已经开始工序的原工位、原团队、时间状态和由此形成的 worker-station binding；
3. 通过 task release time 和 mask 排除尚未释放的延迟工序；
4. 从初始排程 checkpoint warm start：形状一致参数直接复制，扩展后的输入层复制原有 18 列权重，新增加的 6 列保留新模型初始化值；
5. 使用重调度综合塑形目标继续训练，同时在实验中分别报告 makespan、节拍超限与稳定性原始分项。

### 4.5 Algorithm, complexity, and reproducibility

正文提供一个主算法：

1. 构建或更新四类型 APAL 图；
2. 计算 task/station/worker masks；
3. Actor 编码并池化；
4. 依次采样 operation、station 和 $q_i$ 名 worker；
5. 环境校验并执行联合动作，必要时推进到最近事件；
6. 存储联合 log-probability、value、reward 和 masks；
7. 使用 GAE 与 PPO 多轮更新；
8. 在确定性验证中使用 masked argmax，并由统一校验器审计排程。

正式稿同时明确：当 Task mask 全部无效时由事件引擎推进至最近资源或物料事件，无法推进才终止轨迹；每个正工时物理工序只产生一次联合动作，零工时层级不进入策略动作。

复杂度分析至少分开报告：

- 图编码：随关系边数增长，Skill Hub 与 direct 图分别给出边数；
- 解码：$O(|\mathcal{R}_t|+|\mathcal{M}|+q_i|\mathcal{W}|)$；
- rollout：每个物理工序一次联合动作，但无可行动作时由事件引擎推进时间；
- 工程开销：构图、编码、解码和约束校验分别计时，避免只报告模型 forward time。

图编码在固定关系数下记为 $O[LH(Nd^2+Ed)]$；解码在固定网络宽度下记为 $O(|\mathcal O|+5+q_i|\mathcal W|)$。单轨迹复杂度另加入前向分配、合法性校验和无动作时的事件推进成本，不把环境成本隐藏在模型 forward time 中。

可复现性说明包括统一随机种子、带哈希的训练 manifest、解析配置、代码版本、模型规格、行为重放一致性检查、温度零验证与双层合法性审计。确定性算法采用 `warn_only` 且正式训练使用混合精度，因此不承诺跨硬件逐位一致。

# 第五章 Experiments and Results（实验与结果）

> 当前状态：Round 1，待作者确认实验口径。由于最终版 Worker Pointer 尚需加入所选工位嵌入并重新训练，本章先锁定实验问题、比较协议、证据标准和结果组织方式，不把现有临时数值写成最终结论。

## 1. 本章任务与核心论证

第五章不按“数据集—参数—若干表格”的流水账组织，而是回答五个与论文贡献一一对应的实验问题：

1. **EQ1：跨规模泛化**——在有限的小/中规模随机实例上训练后，同一策略能否在不微调的情况下求解规模显著不同的 APAL 实例，并保持完整、合法的联合排程？
2. **EQ2：初始排程质量**——在相同 APAL 数据、资源约束和执行时间模型下，HGP-PPO 能否获得优于或可比于规则、搜索/元启发式和学习型基线的 makespan？
3. **EQ3：机制必要性**——异构关系编码、全局池化、自回归团队构造、工位条件化、动态掩码、Skill Hub 和排程内生工人绑定分别解决了什么问题？哪些模块确有质量或效率贡献？
4. **EQ4：计算与扩展性**——面对数百至三千余道工序，方法的图规模、推理时间、显存/内存和 rollout 开销如何增长？与逐实例搜索相比是否具有可用的摊销推理优势？
5. **EQ5：重调度迁移**——在固定物料扰动导致的工序开始延误场景下，初始排程表示—解码骨架能否通过特征扩展、warm start 和继续训练迁移到重调度，并同时控制 makespan、节拍超限和方案扰动？

本章拟建立的总论点为：

> 在严格隔离训练、模型选择和最终测试数据后，HGP-PPO 应通过同一套可变规模图表示与自回归联合解码器，在未微调的不同规模 APAL 实例上生成合法排程；其竞争力不能只由最终 makespan 表支持，还应由样本效率、模块消融、计算扩展性和固定情景下的重调度迁移共同证明。

该论点目前是**待检验主张**，不是既定结论。尤其需要区分以下三个概念：

- **规模兼容（size compatibility）**：网络结构可以接收不同节点数量；属于方法性质；
- **同一数据族内的跨规模外推（within-family scale extrapolation）**：训练和测试可能共享模板结构，但规模不同；当前已有结果主要属于这一层；
- **跨模板或跨数据集泛化（cross-template/cross-dataset generalization）**：最终测试实例及其拓扑模板未参与样本生成、调参和模型选择；只有完成严格隔离后才可使用这一更强表述。

## 2. 证据分层与报告纪律

### 2.1 三层证据状态

所有结果进入正文前统一标记为：

| 证据等级 | 定义 | 当前可归入的结果 |
|---|---|---|
| **Formal** | 方法版本锁定；数据、seed、checkpoint、解码协议和合法性校验可复现；不存在训练/模型选择/测试混用 | 固定 `physical-v2` manifest 上部分重调度规则、搜索和学习基线；部分已完成的严格消融仍需与最终 Full 版本复核 |
| **Conditional** | 运行真实且可用于判断趋势，但模型未训练完成、方法版本将改变、元数据不完整或测试参与过模型选择 | 当前 Full 初始排程十次结果、旧版消融、当前 Full 重调度、部分 objective-aligned 结果 |
| **Historical/Supplementary** | 旧代码、旧口径、单次验证、不公平训练预算或无法进入当前主协议 | 旧 Basic PPO/DQN、旧 no-pointer 单次结果、部分 CAC 历史结果和自动训练评估 |

正文主表只使用 `Formal` 结果。`Conditional` 结果可在实验开发记录中保留，但在正式论文中必须经过重跑或降格为局限性/补充说明；不同证据等级不得求平均或拼入同一统计结论。

### 2.2 不得混淆的重复类型

- **同一 checkpoint 的确定性重复**只能证明实现可复现，不能当作独立样本；
- **同一 checkpoint 的随机解码重复**反映策略采样波动，不能替代独立训练 seed；
- **独立训练 seed**才用于估计训练稳定性和模型不确定性；
- **不同重调度场景**可作为成对场景样本，但同一基础实例内的场景并非完全独立，统计时需保留分层或聚类结构。

### 2.3 硬性合法性门槛

任何方法只有在统一校验器确认以下条件全部满足后，才进入质量排名：

- 所有物理工序均被且仅被调度一次；
- 工艺前序、站位单调性、固定站位和槽位容量约束满足；
- 工人技能、给定团队人数、工人—站位永久绑定和时间互斥满足；
- 调度输出可完整解析，`complete=1` 且 `valid=1`；
- 重调度额外满足冻结工序、释放时间和基准状态继承约束。

无可行输出的方法报告 `valid rate`、失败原因和修复次数，不以惩罚后的 makespan 与合法方法直接并列排名。

#### 5.2.2 Training, model selection, and locked test split

当前历史配置仍存在两类不符合最终协议的路径：`scale_400_800_schedule.yaml` 使用真实 `680` 作为 checkpoint 选择实例，部分后续筛查配置则使用四真实实例的归一化综合分选择候选。二者都会使 Locked test 信息进入模型选择，因此相关 checkpoint 只能保留为开发或补充证据，不能直接进入正式主结果。正式实验必须改用与训练文件和四个真实实例均分离的 Development manifest。

推荐最终协议为：

1. **Training set**：固定数量的随机 400--800 规模训练实例；锁定生成 seed 和数据清单；
2. **Development set**：与训练文件、生成 seed 和四个最终基准均不重复的固定验证实例，仅用于早停、checkpoint 选择和超参数选择；
3. **Locked test set**：四个实验室基准只在模型与配置锁定后评估，不参与训练、早停或模型选择；
4. **Zero-shot rule**：测试时不进行梯度更新、再训练、实例特定参数搜索或按测试结果挑 checkpoint；
5. **Checkpoint rule**：开发集全部完整合法后，以预先锁定参考值归一化的 makespan 均值选择 checkpoint；非法候选的选择分数为无穷大，并列时取更早候选；
6. **Final repetition**：至少 5 个独立训练 seed；每个 seed 分别按 Development 结果选择 checkpoint，全部进入确定性 masked argmax 测试，不再按测试结果筛 seed；
7. **Version lock**：最终 Full 必须是加入 station embedding 后的同一模型版本；旧 checkpoint 单独标记为 `mask-only worker pointer`，不得混合统计。

若计算预算允许，主结果建议使用 10 个独立训练 seed；最低可接受方案为 5 个独立训练 seed，并同时报告全部 seed 的散点而非只给均值。

中文初稿已将上述协议写入第 5.2.2 节，并同时覆盖重调度：warm-start 初始 checkpoint 必须先锁定，重调度 checkpoint 仅按固定 Development 场景的合法性与 selection score 选择，真实测试场景不得参与目标权重调整。

**写作状态：已完成中文初稿。** 正文已锁定以下层级：初始排程以 makespan 为唯一主要质量指标，relative gap 仅作归一化辅助量且参考值必须事前固定；重调度以 selection score 排序并拆分报告全部质量与稳定性分项；complete/valid 为硬门槛；在线推理、逐实例搜索与离线训练成本分开报告。统计上，初始排程以独立训练 seed 为重复单位，重调度采用“基础实例—扰动场景—训练 seed”的同场景分层配对结构，显著性检验只作辅助并使用 Holm 校正。正式分析不得对 240 个嵌套场景进行忽略基础实例层级的扁平独立样本检验。

- 站位负载分布、技能瓶颈和工人绑定分布，仅用于解释；

- 同时报告绝对差值和相对差值，避免只给 $p$ 值；
- “最佳”必须基于预先声明的主要指标和合法性门槛，不能按不同表格临时切换指标。

正式结果前仍须锁定：每个实例的唯一 $C_j^{\mathrm{ref}}$、bootstrap／置换重复次数与随机 seed，以及四个基础实例内场景阶段和强度的分层数量。

#### 5.3.1 Headline cross-scale evaluation

本节应成为第五章第一张结果表，因为跨规模能力是希望审稿人记住的核心能力。推荐表格按实例规模排列，行是同一个锁定 Full 模型及主要基线，列为：

```text
valid/complete | inference time | template relation
```

四个实例的解释应分层：

- `283`：低于训练范围的向下规模外推；当前不作为直接生成模板，但与上位模板的结构重合待审计；
- `680`：处于训练范围附近，但与当前训练生成模板存在重合；
- `2338`：远高于训练范围，但与当前部分训练生成模板存在重合；
- `3182`：远高于训练范围的向上外推；当前不作为直接生成模板，但可能包含与 2338 相同的数据族结构，需审计后再称模板隔离。

只有当四个实例不再参与 checkpoint 选择后，才能称为 zero-shot test；在当前协议下，现有四规模结果应标记为开发阶段的跨规模验证，而不是最终未见测试。

结果段落按以下顺序写：

1. 先报告所有规模是否合法、完整；
2. 再比较 makespan 与规模增长趋势；
3. 然后讨论训练范围外的下降幅度，而不是只强调最好实例；
4. 最后根据模板隔离审计限定“跨规模”或“跨数据集”措辞。

#### 5.3.2 Sample-efficiency study

“只需少量随机训练样本”必须独立验证，不能由 80 个训练文件直接推断。推荐固定训练环境步数和所有超参数，只改变训练实例池数量：

```text
N_train in {10, 20, 40, 80}
```

每一档使用相同的独立训练 seed，并在同一锁定测试集上报告：

- 四规模 makespan/relative gap；
- 合法率；
- 训练收敛速度；
- 跨 seed 方差；
- 每新增训练实例带来的边际收益。

若不同样本数导致每个实例被访问次数不同，应同时给出两种可解释预算之一：固定总环境步数，测量数据多样性收益；或固定每实例访问次数，测量增加数据与计算的联合收益。主文优先采用固定总环境步数，另一协议可放补充材料。

#### 5.3.3 Training-scale matrix

为证明“可变图输入不等于自然泛化”，建议增加训练规模区间 × 测试规模的矩阵：

```text
train: small-only / 400--800 mixed / large-only or mixed-scale
test: 283 / 680 / 2338 / 3182
```

最低可行版本比较 `single-scale 680` 与 `mixed 400--800`；更完整版本再加入小规模和较大规模训练。该实验用于回答：泛化来自网络结构、规模归一化和训练分布共同作用，还是仅仅因为测试规模被训练模板覆盖。

### 5.4 Initial-scheduling comparisons

#### 5.4.1 Comparison with rules and search methods

先比较规则与搜索方法，因为它们直接反映传统单步优先规则或局部搜索处理工序—工位—工人耦合时的能力边界。结果表必须同时报告方法预算，避免将极轻量 SA/IG/Beam 结果解释为算法本身的极限。

建议主要结论只在证据支持时写成：

- HGP-PPO 是否在多数规模上获得更低 makespan；
- 当搜索方法质量更好时，HGP-PPO 是否在端到端推理时间上表现出摊销优势；
- 规则或搜索失败是否来自局部优先级无法预见后续技能/工位瓶颈，而不是笼统归因于“传统方法落后”。

#### 5.4.2 Comparison with adapted learning baselines

L2D-PPO-APAL 与 Graph-DDQN-APAL 使用相同环境、训练数据和可行性校验。比较应覆盖：

- 单步或有限动作表达能否完成工序—工位—工人团队联合决策；
- 跨规模 makespan 与合法率；
- 训练稳定性和推理时间；
- 是否需要固定最大动作维度或实例特定输出头。

若某基线通过规则补全工位或工人决策，正文必须明确“学习工序顺序 + 规则补全资源”的边界。该组实验也用于回应尚未完成的关键问题：只学习工序顺序或工序—工位是否已经足够。正式结论须等待对应对照实现，不能仅凭结构推断。

### 5.5 Ablation and mechanism studies

消融表不应只列“Full 减一个模块”，而应按贡献链组织。

#### 5.5.1 Representation and global context

1. `Full` vs `w/o relation-aware GAT`：证明关系消息传递整体贡献；若要声称 GAT 注意力优于一般 GNN，应再加入参数量接近的 relation-aware GCN/GraphSAGE；
2. `type-wise attention pooling` vs `mean+max pooling`：检验全局聚合方式；增加注意力权重与瓶颈站位/稀缺技能相关性分析；
3. 报告 makespan、方差、训练曲线和规模外退化，不能只看单一 680 实例。

现有重调度结果中 `w/o GAT` 曾略优于未完成的 Full，因此最终论文不能预设 GAT 在所有任务上都提升。若最终仍出现该现象，应讨论注意力编码在初始排程与重调度中的任务依赖性。

#### 5.5.2 Joint decoder and station-conditioned team construction

至少包含：

- `station-through-mask only` vs `station-embedded Worker Pointer`；
- autoregressive Pointer vs 一个合理、共享相同可行性 mask 的非 Pointer 团队构造器；
- 学习工序顺序 + 规则补全资源；
- 学习工序—工位 + 规则补全工人；
- 完整学习工序—工位—工人团队。

这组实验直接支撑论文最核心的“多资源联合表达与解码”缺口。非 Pointer 对照不能沿用当前明显弱化或无法公平表达团队的旧 no-pointer 实现；应尽量匹配参数量、候选信息和训练预算。

#### 5.5.3 Endogenous worker-to-station binding

推荐新增高优先级对照：

- **Pre-allocation**：排程前按技能/人数或启发式将工人固定分给五个站位，再只优化后续排程；
- **Endogenous binding**：工人由被选站位在排程过程中首次绑定；
- 可选上界/诊断：使用最终任务负荷信息做离线预分配，但必须标明其使用了先验信息。

报告 makespan、站位负载、技能缺口、各站位绑定工人数和最晚绑定时刻。该实验用于验证：由于排程开始前尚不知道各站位最终任务量和技能需求，预分配可能造成不可逆资源失衡，而内生绑定允许工序、站位与工人供给共同形成。

#### 5.5.4 Skill Hub topology and efficiency

比较：

1. direct worker-operation skill edges；
2. forward Skill Hub；
3. bidirectional Skill Hub。

报告边数、峰值显存、图编码时间、rollout throughput、makespan 和合法率。由于三种图的信息方向不完全等价，结果只能解释“拓扑设计的质量—效率权衡”，不能把性能差异全部归因于稀疏化。

#### 5.5.5 Feasibility masks as constraint diagnostics

`no-mask` 当前难以完成可行调度，因此不适合作为普通 makespan 消融。更合理的报告方式是：

- 完整 mask；
- 去除某一层 mask 后的 invalid action、deadlock、repair count 和 valid rate；
- 若实现统一后处理修复，再报告修复时间和修复后 makespan。

该实验支持“动态 mask 在解码过程中维护可行域”的作用，但不应声称 mask 单独从数学上保证所有输出合法；最终仍由环境和校验器审计。

### 5.6 Computational efficiency and scalability

#### 5.6.1 Graph complexity

在四个规模上统计四类节点、各关系边数、图构建时间和编码时间。Skill Hub 与 direct 图按第四章公式给出理论边数，并用真实实例验证增长趋势。图复杂度与解码复杂度分开呈现，避免只给总 wall time 无法定位瓶颈。

#### 5.6.2 End-to-end runtime and memory

端到端剖析至少包括：

- 数据加载与构图；
- GAT 编码与池化；
- Task/Station/Worker 解码；
- 环境状态更新和合法性校验；
- 峰值 GPU 显存、CPU RAM；
- 训练 wall time、环境步/秒、推理 wall time。

当前“由一个 episode 外推约 15.6 小时”的训练时间只能作为开发估计，不能进入正式表。最终运行时间应由完整训练日志或统一 benchmark 脚本重新测量，并注明是否使用 AMP、并行环境和相同硬件。

#### 5.6.3 Quality-time trade-off

用 makespan 对单实例求解时间绘制 Pareto 图。学习方法分别报告：

- 不含训练成本的在线推理；
- 含一次训练成本的总成本；
- 在重复求解多少个实例后摊销成本低于逐实例搜索的 break-even point。

这样可避免仅以神经网络推理速度与搜索总求解时间做不完整比较。

### 5.7 Task-delay rescheduling

#### 5.7.1 Fixed scenario manifest

沿用固定 `physical-v2` 协议：四个名义实例，每个实例 60 个物料扰动导致的工序开始延误场景，共 240 个；每个实例按 low/medium/high 三种强度各 20 个。所有方法读取完全相同的受扰工序、延误量、更新后释放时刻、基准排程和冻结状态。

本节首先说明 release-time 精度修复后的统一环境版本。精度修复前的失败结果只作为实现审计记录，不进入方法质量比较。

#### 5.7.2 Main comparison

主表比较最终 Full、主要规则、Hybrid/repair 规则、Beam/IG/SA、L2D-PPO-APAL 和 Graph-DDQN-APAL，报告：

- 综合 `selection score`；
- makespan 与相对初始排程增量；
- takt violation；
- start-time deviation；
- station-change 和 team-change rate；
- eligible/complete/valid rate；
- 推理时间。

当前临时结果中强规则 `HybridCPMStabilityRepair` 的综合分可能优于未完成的 Full，且 no-GAT 曾略优于 Full。最终正文必须如实保留最强基线；只有最终模型重训后确有证据，才能声称全面优于传统方法。否则应将贡献写成跨规模、统一表示和可迁移性，而不是所有指标绝对领先。

#### 5.7.3 Scale and disturbance intensity

将 240 场景按基础规模与延误强度分层，回答：

- 性能是否随规模增长稳定；
- 高强度延误下 makespan 与稳定性权衡是否改变；
- 哪些实例或情景导致节拍超限；
- 学习方法的优势是否只出现在特定强度。

结果图建议使用每情景成对差值分布，而不是仅给四个总体均值。

#### 5.7.4 Warm start and transfer mechanism

比较相同重调度架构的：

- 从初始排程 checkpoint warm start；
- 随机初始化训练；
- 可选：冻结图编码器后只训练扩展输入层/解码器。

报告达到固定验证分数所需环境步数、最终 score、训练方差和合法率。该实验支持“同一表示—解码骨架可迁移”，但不能写成“同一个未经修改的模型直接解决初始排程与重调度”。

### 5.8 Robustness, failure modes, and claim boundaries

本节主动报告以下边界：

1. **模板依赖**：同模板族与模板隔离实例的性能差异；
2. **规模外推失效点**：随着工序数、工人数或图边数增长，makespan 和运行时间何时明显恶化；
3. **技能瓶颈**：稀缺技能比例或可用工人数变化时的质量和合法率；
4. **训练不稳定性**：最差 seed、方差、崩溃/无可行策略的训练比例；
5. **失败排程审计**：invalid action、deadlock、缺失工序和释放时间精度问题；
6. **组合解码局限**：团队人数由工序需求给定；顺序生成路径对应无序集合，但未对等价排列概率求和。

若计算预算有限，主文最低保留模板隔离、最差 seed 和一个技能瓶颈压力测试，其余放补充材料。

### 5.9 Answers to evaluation questions

章末不再重复所有数值，而是逐条回答 EQ1--EQ5，每个回答使用“结论强度 + 证据 + 边界”的格式。例如：

```text

Evidence: Table X and Fig. Y.

template-disjoint protocol removes this concern.
```

## 9. Provisional Chapter Summary: Experiments and Results

**Core Purpose**：用严格隔离的跨规模测试、传统与学习基线、机制消融、效率剖析和固定场景重调度，验证 HGP-PPO 是否真正解决 APAL 的多资源联合表达与决策问题。

**Core Argument**：最重要的证据不是单一实例上的最低 makespan，而是同一锁定策略在训练范围内外均保持合法、具有竞争性的排程质量，并且该能力能由可变规模表示、自回归联合解码、全局感知和内生资源绑定的对照实验解释。

**Evidence Available**：四规模初始结果、多种规则/搜索结果、Graph-DDQN 结果、部分消融、240 个固定物料扰动导致的工序开始延误场景及多种重调度基线。
