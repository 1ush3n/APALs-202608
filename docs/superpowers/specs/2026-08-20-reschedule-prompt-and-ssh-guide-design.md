## 范围与边界

### 重调度提示词

提示词只负责 APAL 重调度研究、代码协作、实验执行和结果核验，重点覆盖：

- 动态扰动、重调度时刻、冻结区间、释放时间与初始排程继承；
- HB-GAT-PPO 主方法、学习型 baseline、规则修复和搜索式 baseline；
- 完整性、硬约束、公平性、统一 manifest、训练/正式验证边界；
- 训练、验证、消融、结果重算和归档；
- 修改代码时的最小改动、测试、Git 提交与远程同步纪律。

提示词明确禁止把 APAL 重调度泛化成 FJSP，也禁止把动态重调度结果冒充初始调度核心贡献。远程服务器连接细节不复制到提示词中，只要求需要远程执行时遵守 SSH 指南。

### SSH 指南

指南保留通用连接模板，但修正当前实例相关示例并补充以下事实：

- 服务器实际使用 `/root/miniconda3` 的 `base` 环境或绝对 Python 路径，不使用不存在的 `rag_env`；
- 当前项目实际目录为 `/root/autodl-tmp/APALs-202608-clean`，同时提醒路径和端口必须以控制台为准；
- 无卡模式只用于同步/调试，GPU 模式启动后先检查 `nvidia-smi` 和 PyTorch CUDA；
- 长任务应使用 `screen`、`tmux` 或 `nohup`，SSH 断开后用 `--resume` 恢复；
- 并行任务使用独立命令/会话，避免 Shell 对 `&` 和 `&&` 的歧义；
- 补充磁盘空间、网络加速、SSH 关机和 AutoDL 控制台切换卡模式的边界。

不修改训练、验证或远程控制代码，不写入密码、私钥、令牌或认证文件，不新增依赖。
