## 2. 本地 Overleaf-like 工作流

本项目没有部署完整 Overleaf CE，因为当前需求是不需要多人协作。当前采用的是更轻量的本地方案：

```text
Codex / VS Code / 本地编辑器
        ↓
scripts/compile_latex.py
        ↓
latexmk
        ↓
pdflatex
        ↓
PDF 输出
```

这种方式适合：

- 让 Codex 直接修改 `.tex`、`.bib`、`.sty`、`.cls` 文件。
- 让 Codex 编译论文并根据 `.log` 定位错误。
- 自动处理引用、目录、交叉引用所需的多轮编译。
- 在单人论文写作场景中替代 Overleaf 的大部分编译能力。

这种方式不提供：

- 浏览器在线编辑界面。
- 多人协作。
- Overleaf 项目管理界面。

## 3. LaTeX 编译脚本

编译入口文件：

```text
scripts/compile_latex.py
```

推荐直接使用 `rag_env` 中的 Python 运行：

```powershell
C:\Users\13575\miniconda3\envs\rag_env\python.exe scripts\compile_latex.py paper\main.tex
```

如果你已经激活 `rag_env`：

```powershell
python scripts\compile_latex.py paper\main.tex
```

其中 `paper\main.tex` 替换为你的 LaTeX 主文件路径。

### 3.1 普通编译

```powershell
python scripts\compile_latex.py paper\main.tex
```

该命令会调用：

```text
latexmk -pdf -synctex=1 -interaction=nonstopmode -halt-on-error
```

适合日常论文编译。

### 3.2 持续监听编译

```powershell
python scripts\compile_latex.py paper\main.tex --watch
```

该模式会让 `latexmk` 持续监听文件变化，接近 Overleaf 自动重编译体验。适合你一边编辑论文、一边查看 PDF。

### 3.3 清理中间文件

```powershell
python scripts\compile_latex.py paper\main.tex --clean
```

用于清理 LaTeX 中间产物，例如：

```text
.aux
.log
.fls
.fdb_latexmk
.synctex.gz
```

## 4. 为什么不推荐直接使用 conda run

当前 Windows 控制台环境中，`conda run -n rag_env ...` 在打印 LaTeX 输出时可能触发 GBK/Unicode 编码错误。

因此推荐使用：

```powershell
C:\Users\13575\miniconda3\envs\rag_env\python.exe scripts\compile_latex.py paper\main.tex
```

或先激活环境：

```powershell
conda activate rag_env
python scripts\compile_latex.py paper\main.tex
```

## 9. 常见问题

### 9.1 提示缺少 LaTeX 包怎么办？

优先重新运行：

```powershell
python scripts\compile_latex.py paper\main.tex
```

MiKTeX 已启用自动安装缺失包。如果仍失败，把 `.log` 中的缺包信息交给 Codex 处理。

### 9.2 编译失败时应该给 Codex 什么信息？

优先给：

```text
主 .tex 文件路径
.log 文件
.bib 文件
模板 .cls / .sty 文件
错误截图或终端输出
```

### 9.3 什么时候需要真正部署 Overleaf CE？

只有在以下需求明确出现时才建议部署：

- 多人协作。
- 浏览器在线编辑。
- 项目权限管理。
- 希望完全复刻 Overleaf Web 界面。

如果只是单人论文写作和 AI 辅助编译，当前方案更轻、更直接。
