# APAL 当前版本命令使用手册

本文档按功能列出当前代码的推荐运行命令。主线训练、验证和新增重调度实验入口均使用 Hydra 原生 `key=value` 参数格式；旧式 `--config`、`--set`、`--trainer legacy` 已不用于主线入口。

## 0. 通用规则

### 0.1 进入环境

Windows:

```powershell
conda activate rag_env
cd D:\OneDrive\研究生\HGP-期刊\APAL-Dynamic-v4
```

Linux:

```bash
conda activate rag_env
cd /root/autodl-tmp/APAL-Dynamic-v4
```

### 0.2 Hydra 参数写法

主线入口统一使用：

```bash
python train.py experiment=initial_schedule_283 train.batch_size=32 train.num_envs=4
```

常用覆盖项：

```bash
train.batch_size=16
train.accumulation_steps=16
train.max_episodes=300
train.eval_freq=1
train.num_envs=16
train.lr=5e-5
train.seed=42
rollout.rollout_heartbeat_interval_sec=0
rollout.enable_rollout_profiler=true
model.use_skill_hub=true
model.skill_hub_bidirectional=true
logging.run_id=my_run_name
logging.artifact_layout=runs
logging.log_dir=/root/tf-logs
```

说明：

- Windows/Linux 硬件配置会自动选择，不需要传 `hardware=...`。
- Windows 默认使用 `conf/hardware/windows_4060_low_memory.yaml`。
- Linux 默认使用 `conf/hardware/linux_server.yaml`。
- checkpoint 会自动携带并读取模型结构元数据，验证时通常不需要手动记忆是否启用了 Skill Hub。
- 如果显式覆盖模型结构参数，且与 checkpoint 不一致，评估入口会报错，避免误评估。

### 2.6 初始调度异步验证与保存

单实例初始调度可让训练进程独占 GPU，由独立 CPU worker 在固定 Standard 场景验证每个成功 PPO episode，并按 Makespan 原子更新 best：

```bash
python train.py \
  experiment=initial_schedule_680 \
  experiment_name=initial_680_async_seed42 \
  async_eval_enabled=true \
  async_eval_initial_data_path=data/680.csv \
  async_eval_cpu_threads=4 \
  async_eval_queue_capacity=4 \
  async_eval_wait_on_finish=true \
  eval_freq=1 \
  eval_temperature=0.0 \
  seed=42
```

说明：

- 单实例异步模式仅允许 `eval_scenarios=[standard]`，只有完整排程可覆盖 best。
- 初始调度异步模式固定只验证 `async_eval_initial_data_path`（默认 `data/680.csv`）及其固定工人池；即使训练配置启用了多基准验证，也不会运行 283/2338/3182。
- 队列满时训练等待，不丢弃 episode；中断后使用相同 `run_id` 和 `resume=true` 可恢复候选队列。
- 队列、逐 episode 指标和异步 TensorBoard 位于当前运行的 `checkpoints/async_eval/`。

## 4. 重调度：场景库生成

### 4.1 生成固定低/中/高任务延迟场景

```bash
python scripts/generate_reschedule_load_scenarios.py \
  experiment=reschedule_task_delay \
  seed=20260701 \
  scenarios_per_level=20 \
  baseline_path=results/final_schedule.csv \
```

输出：

- `data/reschedule_scenarios/task_delay_load_grid_seed20260701.metadata.json`

扰动等级含义：

- `low`：较早重调度、较低延迟任务比例、短延迟。
- `medium`：中期重调度、中等延迟任务比例、中等延迟。
- `high`：较晚重调度、较高延迟任务比例、长延迟。

场景文件由固定种子生成，可复现；PPO、规则 baseline 和搜索式 baseline 共享同一场景 CSV。

### 4.2 本地小规模 Beam/IG/SA 搜索

该入口与模型训练无关，也不会修改原 manifest 或60场景文件。它只针对一个实例选择
`low_000`、`medium_000`、`high_000`，分别运行 Beam、IG、SA，共9个任务。默认使用完整搜索预算，并以3个进程适配16GB内存的本地电脑。

```powershell
python scripts/evaluate_reschedule_search_small.py `
  experiment=reschedule_task_delay `
  manifest_path=data/reschedule_manifests/reschedule_400_600_seed20260701_physical_v2.json `
  instance_id=real_680 `
  scenario_index=0 `
  parallel_workers=3 `
  output_dir=results/04_reschedule_baselines/search_small_3scenario/real_680_idx000_seed42
```

中断后使用完全相同的命令即可继续。脚本默认 `resume_partial=true`、`flush_every=1`，每完成一个搜索任务都会保存断点。若要选择每个等级的第6个固定场景，可传 `scenario_index=5`；若确需清空断点重算，显式传 `force_rerun=true`。

```bash
python train.py \
  experiment=reschedule_task_delay \
```

### 5.3 多实例重调度训练数据准备

论文主实验建议使用 30 个 400-600 工序随机实例训练重调度模型，并用真实 680 数据集固定验证保存 best model。先批量生成训练实例、baseline schedule 和真实数据固定扰动场景：

```bash
python scripts/prepare_reschedule_data.py \
  experiment=reschedule_task_delay \
  initial_model_path=checkpoints/initial_schedule/bestmodel/best_model.pth \
  train_count=30 \
  min_ops=400 \
  max_ops=600 \
  seed=20260701 \
  output_manifest=data/reschedule_manifests/reschedule_400_600_seed20260701.json
```

然后用 manifest 启动重调度训练。训练时会在 400-600 随机实例中切换，并按当前实例自动读取对应 baseline；`reschedule_baseline_model_path` 用于 warm start 初始化重调度策略；自动验证固定使用 `real_680`：

```bash
python train.py \
  experiment=reschedule_task_delay \
  train_data_path_or_dir=data/generated/reschedule_train_400_600 \
  reschedule_baseline_model_path=checkpoints/initial_schedule/bestmodel/best_model.pth \
  reschedule_manifest_path=data/reschedule_manifests/reschedule_400_600_seed20260701.json \
  reschedule_eval_instance_id=real_680 \
  train.batch_size=128
```

### 5.4 GPU 训练与 CPU 验证异步分离

异步验证支持 Lightning 初始调度与重调度训练。下面的重调度命令让训练进程独占 GPU，独立 worker 使用 4 个 CPU 线程；每个成功提交的 PPO episode 都验证固定 `real_680/medium_000`，队列上限为 4，满队列时训练等待而不是丢任务：

```bash
python train.py \
  experiment=reschedule_task_delay \
  experiment_name=reschedule_hgppo_objective_aligned_async_seed42 \
  train_data_path_or_dir=data/generated/reschedule_train_400_600 \
  reschedule_baseline_model_path=checkpoints/initial_schedule/bestmodel/best_model.pth \
  reschedule_manifest_path=data/reschedule_manifests/reschedule_400_600_seed20260701_physical_v2.json \
  reschedule_eval_instance_id=real_680 \
  async_eval_enabled=true \
  async_eval_instance_id=real_680 \
  async_eval_scenario_id=medium_000 \
  async_eval_cpu_threads=4 \
  async_eval_queue_capacity=4 \
  async_eval_wait_on_finish=true \
  eval_freq=1 \
  seed=42
```

说明：

- OOM 回滚的 PPO 更新不会入队，也不会生成该轮候选模型。
- `last.ckpt` 在候选入队前原子更新；只有 `eligible=1` 且 `selection_score` 改善时才原子更新 `best.ckpt`。
- 队列、逐 episode JSON/CSV、best 排程与异步 TensorBoard 位于当前运行的 `checkpoints/async_eval/`。
- 正常结束会等待队列清空；异常中断保留候选和队列，使用相同 `run_id`、相同命令并增加 `resume=true` 可恢复。
- 该固定单场景只服务训练期 best 选择，论文结果仍使用第 6 节的 manifest 全场景验证。

### 7.7 训练 L2D-PPO-APAL

L2D-PPO-APAL 现在复用主方法的 `APALRolloutService` 和 `VectorEnv`。每个
episode 表示一次 PPO 更新，并包含 `num_envs` 条并行轨迹；Linux 硬件配置自动使用
16 个环境，Windows 低显存配置自动使用 2 个环境。一次更新内所有环境共享同一个
训练数据集，并使用主方法配置的随机工时/工人策略。

```bash
python baselines/literature_ppo/train_l2d_ppo_apal.py \
  experiment=scale_400_800_schedule \
  train_data_path_or_dir=data/scale_400_800_datasets \
  data_file_path=data/680.csv \
  max_episodes=300 \
  train.batch_size=64 \
  literature_ppo_enable_vector_env=true \
  seed=42 \
  output_dir=results/l2d_ppo_apal_initial_680_seed42
```

中断后使用完全相同的输出目录并增加 `resume=true`。`max_episodes` 是总更新次数，
恢复会从 checkpoint 中记录的 `episode+1` 开始，并恢复 optimizer、AMP scaler、
最优指标和数据集选择状态。

```bash
python baselines/literature_ppo/train_l2d_ppo_apal.py \
  experiment=scale_400_800_schedule \
  train_data_path_or_dir=data/scale_400_800_datasets \
  data_file_path=data/680.csv \
  max_episodes=300 \
  train.batch_size=64 \
  literature_ppo_enable_vector_env=true \
  seed=42 \
  output_dir=results/l2d_ppo_apal_initial_680_seed42 \
  resume=true
```

如需确定性单环境 smoke test，可显式设置 `literature_ppo_enable_vector_env=false`；
正式服务器训练不应关闭该开关。

### 7.8 训练 Graph-DDQN-APAL

Graph-DDQN-APAL 使用与主方法一致的 APAL 异构图观测、动作合法性 mask 和环境奖励。默认启用批量 replay，`ddqn_updates_per_transition=0.125` 表示平均每 8 条 transition 更新一次网络。

```bash
python baselines/literature_dqn/train_graph_ddqn_apal.py \
  experiment=scale_400_800_schedule \
  train_data_path_or_dir=data/scale_400_800_datasets \
  data_file_path=data/680.csv \
  max_episodes=300 \
  train.batch_size=64 \
  ddqn_updates_per_transition=0.125 \
  seed=42 \
  output_dir=results/graph_ddqn_apal_680
```

Linux 上可追加以下参数启用 8 环境同步向量采样。`max_episodes` 仍是完成的轨迹总数：

```text
ddqn_enable_vector_env=true ddqn_num_envs=8 ddqn_enable_ipc_fusion=true
```

Windows 硬件配置会自动将 `ddqn_num_envs` 解析为 2。`max_episodes` 表示总轨迹数；
恢复训练从 `episode+1` 开始。向量 wave 内的环境共享数据集，避免并行进程之间产生
不公平的数据集抽样差异。

继续训练时复用原输出目录：

```bash
python baselines/literature_dqn/train_graph_ddqn_apal.py \
  experiment=scale_400_800_schedule \
  train_data_path_or_dir=data/scale_400_800_datasets \
  data_file_path=data/680.csv \
  max_episodes=300 \
  train.batch_size=64 \
  ddqn_updates_per_transition=0.125 \
  seed=42 \
  output_dir=results/graph_ddqn_apal_680 \
  resume=true
```

默认精确恢复文件为 `graph_ddqn_apal_exact_resume.pth`、`graph_ddqn_apal_exact_resume.replay.pt.gz` 和 `graph_ddqn_apal_exact_resume.json`。三者同时存在且哈希匹配时，replay buffer、UTD credit 和随机数状态会一并恢复；缺失时兼容回退到 latest checkpoint 并重新预热 replay。

## 8. 重调度对比算法

### 8.1 重调度规则 baseline

论文对比推荐使用 manifest 模式。它会和 `evaluate_reschedule_manifest.py` 一样，从同一个 manifest 读取 `data_path`、`baseline_schedule_path` 和固定 `scenario_path`，避免手工路径错配。

```bash
python scripts/evaluate_reschedule_rules.py \
  experiment=reschedule_task_delay \
  manifest_path=data/reschedule_manifests/reschedule_400_600_seed20260701.json \
  instance_ids=[real_680] \
  output_dir=results/reschedule_rules_real_680
```

和 PPO 对比时，PPO 也必须使用同一个 manifest 和同一个 `instance_ids`：

```bash
python scripts/evaluate_reschedule_manifest.py \
  experiment=reschedule_task_delay \
  model_path=checkpoints/reschedule_task_delay/bestmodel/best_model.pth \
  manifest_path=data/reschedule_manifests/reschedule_400_600_seed20260701.json \
  instance_ids=[real_680] \
  output_dir=results/reschedule_manifest_eval_real_680
```

手动路径模式仍然保留，但必须保证三者属于同一个实例：`scenario_path` 是由 `baseline_path` 生成，`baseline_path` 是由 `data_path` 生成。


## 10. 输出目录说明

### 10.1 默认 runs 布局

当 `artifact_layout=runs` 时，默认输出到：

```text
runs/<experiment_name>/<run_id>/
  checkpoints/
    best.ckpt
    last.ckpt
    legacy/
      best_model.pth
      latest_checkpoint.pth
      best_model_meta.json
  logs/
    tensorboard/
  eval/
  artifacts/
  configs/
    resolved_config.yaml
    run_manifest.json
```

### 10.2 显式输出目录

多数评估脚本支持 `output_dir=...`，显式传入后会写到指定目录：

```bash
python evaluate_model.py experiment=initial_schedule_283 model_path=... output_dir=results/my_eval
```

### 10.3 TensorBoard

配置中 `log_dir` 固定为：

```text
/root/tf-logs
```

如果使用 `artifact_layout=runs`，训练过程也会在 run 目录下创建：

```text
runs/<experiment_name>/<run_id>/logs/tensorboard/
```

查看 TensorBoard：

```bash
tensorboard --logdir /root/tf-logs --host 0.0.0.0 --port 6006
```
