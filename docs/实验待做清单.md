> 版本说明：本文中 2026-07-17 之前的结果路径均为历史记录；对应文件已移入 `archive/experiments_pre_20260717_buggy_version/results/`。自 2026-07-17 起的活动结果以 `results/` 新版本目录和 `results/experiment_master_results.csv` 为准。

- `已完成`：已有脚本、结果或文档记录，后续只需复核。
- `部分完成`：已有实现或部分结果，但还需要补实验、补汇总或统一口径。
- `待做`：尚未系统执行或缺少可靠结果。
- `可选`：适合放入补充材料，优先级低于主论文核心实验。

## 12. 当前最高优先级任务

1. 优先完成两项核心问题证据：`operation-only → operation-station → operation-station-worker` 动作深度，以及公平的人员预分配与排程内生绑定对比。
2. 重定义并完成三项机制消融：关系感知 GAT / 关系合并 GNN / 无消息传递，attention / mean+max / local-only，全自回归 / independent top-q / no-pointer MLP。
3. 完成所有 baseline 的新版本统一验证：HGP-PPO、L2D-PPO-APAL、Graph-DDQN-APAL、Beam、IG、SA、规则方法；搜索方法补齐四实例并报告预算曲线。
4. 生成严格跨规模泛化矩阵，并补充归一化和训练域随机化消融；固定 checkpoint 后不得再用四个报告实例选择模型。
5. 完成 station embedding 对比、Skill Hub 复杂度与技能瓶颈实验；动态掩码只做非法动作/死锁诊断，不训练普通 `no-mask` 质量基线。
6. 生成重调度低/中/高扰动强度总表，并补 warm start 与目标权重敏感性；所有方法必须同 manifest、同场景、同评价指标。
7. 汇总资源与效率结果：rollout SPS、构图耗时、推理耗时、显存峰值、搜索算法预算—质量曲线。

## 13. 结果落盘建议

建议后续统一按以下结构保存实验结果，避免结果分散：

```text
results/
  paper_experiments/
    initial_main/
    initial_baselines/
    initial_ablation/
    initial_generalization/
    reschedule_main/
    reschedule_baselines/
    reschedule_robustness/
    efficiency/
    figures/
```

每个实验目录至少保留：

- `run_manifest.json`：命令、配置、seed、git commit、时间。
- `resolved_config.yaml`：完整展开后的配置。
- `metrics.csv`：逐场景或逐实例明细。
- `summary.csv`：论文表格可直接使用的汇总。

## 15. 证据导向实验审计

本节按论文主张反推最小实验集合。实验名称与论文结论必须一一对应，不能用相邻但不同的消融替代。

### 15.1 核心证据：正文必须完成

| 论文主张 | 最小可区分实验 | 当前判断 |
|---|---|---|
| 工序—站位—具体工人团队联合决策有必要 | operation-only、operation-station、full joint 三档动作深度；其余环境、训练预算和合法性校验一致 | 新增，最高优先级 |
| 人员资源应随站位任务量和技能需求内生配置 | 公平技能配额的排程前预分配 vs schedule-endogenous binding | 新增，最高优先级 |
| 团队的序贯历史条件化有作用 | full autoregressive vs 不使用团队历史的 independent top-q；当前 `no-pointer` 不足以回答 | 需重定义 |
| 异构关系建模而非一般图传播有效 | relation-aware heterogeneous GAT vs relation-collapsed/shared-weight GNN vs no message passing | 当前 `w/o GAT` 只覆盖最后一档 |
| 全局感知而非仅注意力权重有效 | attention pooling vs mean+max pooling vs local-only | 当前 `no-attention` 只比较前两档 |
| 同一策略具有可信的跨规模能力 | 锁定 checkpoint、无微调评价四规模；报告合法率、makespan 与推理时间，并隔离 checkpoint 选择 | 部分具备，协议需收紧 |
| 少量随机样本可迁移到资源配置差异显著的实例 | 完整属性随机化 vs 当前仅工时/工人子池随机化 vs 固定属性；保存实例级随机化元数据 | 需先实现需求人数与技能需求随机化，或降低主张强度 |

### 15.2 增强证据：正文或补充材料

| 论文主张 | 建议实验 | 当前判断 |
|---|---|---|
| 工位信息应直接影响团队打分 | station mask-only vs station embedding | 已计划，需完成 |
| 跨规模能力来自可解释机制 | full vs no instance normalization；full domain randomization vs fixed attributes | 新增，高优先级 |
| Skill Hub 有语义和效率价值 | direct edges、单向 hub、双向 hub；普通与技能瓶颈场景，同时报告边数、时间和 makespan | 五类技能数据已修正，可开始设计 |
| reward shaping 只是训练技巧 | makespan-only vs full shaping，报告最终 makespan、收敛速度和负荷标准差 | 新增，中优先级 |
| 初始模型可迁移到重调度 | warm start vs scratch，多 seed 比较收敛速度和最终分项 | 已计划，需完成 |
| 重调度结论不依赖单一人工权重 | 至少三组主要权重，报告 makespan 与稳定性分项或 Pareto 关系 | 新增，高优先级 |
| 学习方法优于逐实例搜索 | Beam、IG、SA 低/中/高预算的质量—时间曲线 | 当前新版本仅部分实例、部分预算 |

### 15.3 不建议新增为正文主消融

- 不需要消融 Actor 与 Critic 是否分离；这是较小的实现选择，不承载核心论文主张。
- 不把 AMP、TF32、缓存开关和 DataLoader 参数作为算法贡献，只报告其资源影响。
- 不训练无法产生合法动作的普通 `no-mask` 模型；改为记录非法动作率、死锁率、修复率和合法率。
- 不必全面扫描 GAT 层数、隐藏维度等超参数；除非最终结果对配置异常敏感，否则放入有限敏感性分析即可。

### 15.4 统一实验控制与节省算力的执行顺序

1. 所有学习型消融至少使用 3 个独立训练 seed；主模型和最关键的动作深度、内生绑定对比优先使用 5 个 seed。报告均值、标准差、逐实例差值和置信区间，不用多个推理 seed 冒充独立训练重复。
2. 各对比保持相同训练实例、环境步数、并行环境数、优化器预算、验证规则和合法性审计；模型容量尽量匹配，无法匹配时同时报告参数量。
3. checkpoint 只能由独立开发集选择。四个最终报告实例若参与 best-checkpoint 选择，只能称 cross-scale validation；隔离后才称 held-out test。
4. 第一阶段只在初始排程训练核心消融，并用同一 checkpoint 评价四规模；不必把所有结构消融在重调度上重复一遍。重调度优先完成 warm start、目标权重敏感性和统一 baseline。
