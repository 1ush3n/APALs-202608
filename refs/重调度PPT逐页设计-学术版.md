### 讲稿

> 各位老师好，我汇报的工作是飞机脉动装配线中的预测-反应式重调度方法。
>
> 首先给出问题的形式化定义。左边是符号体系：我们有一个已经优化好的初始调度方案 π₀，它的最大完工时间 M₀ 被定义为系统的节拍时间，记为 T。在生产执行到时刻 t* 时，部分工序因物料延迟无法按原计划开工。此时，那些已经开工的任务形成冻结集合 F，它们的位置、团队、时间都不可修改；未开工的任务形成可重调度集合 U，其中有一个子集 D 被延迟，它们的物料释放时间被推后到 rᵢ。
>
> 右边是三个优化目标的数学表达。目标一是最小化新方案的总完工时间；目标二是控制节拍超期率；目标三是最大化方案的稳定性——包括站位变更率、团队变更率、以及开工时间偏离的绝对值。这三个目标之间存在天然的权衡：要缩小完工时间往往需要改变原方案的布局，但这会损害稳定性。
>
> 这个问题本质上是一个带冻结约束的多目标重调度问题。我们的方法是用强化学习来求解，核心思路是把初始方案的信息编码到状态空间中，引导智能体在微调中平衡这三个目标。

### 关键符号表（可作为页面底部注释栏）

| 符号 | 含义 |
|:---:|------|
| π₀ | 初始调度方案（Baseline） |
| T | 节拍时间 = makespan(π₀) |
| t* | 重调度触发时刻（0.15T ~ 0.65T） |
| F | 冻结任务集（sᵢ ≤ t*） |
| U | 可重调度任务集（sᵢ > t*） |
| D | 延迟任务子集（rᵢ > sᵢ） |

### 讲稿

> 在进入方法之前，简要回顾相关工作。
>
> 重调度领域有两个主流范式：预测-反应式和主动-鲁棒式。我们的工作属于前者——在扰动发生后被动响应，重新生成方案。APAL 调度的求解方法包括遗传算法、启发式规则、以及我们课题组前期的基于图注意力网络的强化学习方法。在 RL 与约束优化结合方面，PPO 配合动作掩码已经被证明可以有效处理组合约束。
>
> 但现有方法存在三个不足。第一，完全重排丢弃了初始方案的结构信息，导致现场扰动过大；第二，纯启发式修复缺乏全局优化能力；第三，已有 RL 方法没有利用初始调度模型的知识迁移。我们的工作针对这三个 gap 提出解决方案：将初始方案编码为状态特征、设计多目标奖励函数、建立约束自动审计体系。

### 讲稿

> 这一页概述我们的方法框架。核心思想非常直接：我们不是从零开始训练一个重调度模型，而是把初始方案的信息作为额外的输入维度交给强化学习智能体，让它在"靠近 baseline"的流形上进行微调式探索。
>
> 流程分为四个阶段。首先，延迟场景生成器根据设定的概率分布采样重调度时刻和延迟任务。然后，冻结恢复模块将环境中已经发生的历史状态完整重构——包括已开工任务的站位绑定、工人锁定、工艺后继解锁等。第三阶段是关键创新点：Baseline 引导状态编码，将初始方案中的任务级信息（站位置、团队规模、是否冻结、是否延迟、延误程度等）作为额外的 6 维特征拼接到图神经网络的 Task 节点输入中，形成 24 维的增强状态表示。第四阶段，PPO 智能体在这个增强状态空间中进行微调式训练，动作空间不变，但奖励函数增加了节拍保真度和稳定性项。最终输出重调度方案和全量合规性审计报告。

### 关键公式

\[
\mathbf{x}_i^{\text{aug}} = [\underbrace{\mathbf{x}_i^{\text{base}}}_{18\text{ dim}} \;\|\; \underbrace{\phi(\pi_0(i), t)}_{6\text{ dim}}] \in \mathbb{R}^{24}
\]

其中 \(\phi(\pi_0(i), t)\) 将 baseline 中第 i 个任务的信息与当前时刻 t 编码为引导特征向量（详见第 5 页）。

## 第 4 页 · 延迟场景建模与冻结约束恢复

### 排版布局

```
┌──────────────────────────────────────────────────────────┐
│  标题栏：延迟场景建模与冻结约束的数学恢复                      │
└──────────────────────────────────────────────────────────┘

  ┌─── 左 45%：场景生成（随机过程） ────────────────────────┐
  │                                                        │
  │   重调度时刻：                                           │
  │     t* ~ Uniform(0.15T, 0.65T)                         │
  │                                                        │
  │   延迟任务选择（伯努利过程）：                              │
  │     ∀i ∈ U,  P(i ∈ D) = p_delay = 0.15               │
  │                                                        │
  │   释放时间：                                             │
  │     rᵢ = max{sᵢ, t* + Uniform(δ_min, δ_max)}           │
  │                                                        │
  │   约束条件：                                             │
  │     s'ᵢ ≥ rᵢ  (硬约束，通过 ActionMasker 保证)           │
  └────────────────────────────────────────────────────────┘

  ┌─── 右 55%：冻结恢复（确定性的束传播）────────────────────┐
  │                                                        │
  │   对每个 i ∈ F（冻结任务），递归恢复物理状态：              │
  │                                                        │
  │   (1) Task Status                                      │
  │     status(i) ← 2   (标记为已完成)                       │
  │                                                        │
  │   (2) Station Load                                     │
  │     L_{σᵢ} += dᵢ · |ωᵢ|    (负载累加)                  │
  │                                                        │
  │   (3) Worker Binding (APAL特有约束)                     │
  │     ∀w ∈ ωᵢ:                                           │
  │       free_time(w) = max(free_time(w), eᵢ)            │
  │       lock(w) = σᵢ + 1        (终生绑定, 不可跨站)      │
  │                                                        │
  │   (4) Precedence Cascading                             │
  │     若 eᵢ ≤ t*:                                        │
  │       ∀j ∈ succ(i): completed_preds(j) += 1            │
  │     否则:                                               │
  │       注入 TASK_FINISH 事件到时刻 eᵢ                     │
  │                                                        │
  │   (5) 下界估计                                          │
  │     LB = max( max(eᵢ|i∈F),  t*+ Σdⱼ/(N·K),            │
  │               max(rⱼ|j∈U) )                            │
  └────────────────────────────────────────────────────────┘
```

### 讲稿

> 这一页讲两个关键的建模步骤：场景生成和冻结约束恢复。
>
> 左边是延迟场景的随机过程建模。重调度时刻 t* 在节拍的 15% 到 65% 之间均匀采样——这个范围经过分析，确保冻结任务数量足够但又不过多。每个可移动任务以 15% 的概率被独立地标记为延迟。释放时间的计算公式保证延迟只推后不提前，且通过 ActionMasker 实施为硬约束。
>
> 右边是冻结约束的确定性恢复。这是一个束传播过程：对每个冻结任务，我们需要按因果链恢复它对环境的全部副作用。第一是标记状态；第二是累加站位负载；第三是恢复工人绑定——这里有一个 APAL 特有的约束：工人一旦被分配到某站位，终生绑定，不能跨站流转。第四是工艺优先级的级联恢复——如果冻结任务已经完成了，需要手动推进它的后继任务的前置计数；如果还没完成，则注入仿真事件等待未来触发。第五衍生出一个理论下界，用来判断在当前扰动下节拍是否还可达。
>
> 这个下界的实用价值在于：如果它已经超过了初始方案的 makespan，意味着无论如何都不可能在原节拍内完工，我们就自动放松稳定性惩罚的权重，让模型优先追求完工而非跟随 baseline。

### 讲稿

> 第五页讲的是我们方法最核心的贡献：如何把初始方案的信息编码为图神经网络可以理解的特征。
>
> 我们的设计哲学是"在参考解附近搜索"，而不是在全空间中盲目探索。为此，我们在每个 Task 节点的输入上增加了 6 个维度，全部来自 initial schedule 的已知信息。
>
> 维度 18 是时间偏移——距离 baseline 计划开工时间还剩多久。它的关键是负值：当 current time 已经超过了 baseline 的开工时间，这个值变负，网络接收到一个明确的"这个任务已经被耽误了"的信号。维度 19 和 20 提供站位和团队的参考值——它们不是硬约束，而是软引导，通过奖励函数驱动模型在大多数情况下自然地选择与 baseline 一致的站位和团队。维度 21 和 22 是二值硬标记——哪些任务不可改、哪些任务出了延迟问题。维度 23 是我们最新加入的特征——延误比率，它在任务过时但未完工时持续增长，形成一个随时间单调递增的紧迫感梯度。
>
> 底部提炼了三个方法论的 insight。第一，维度 18 和 23 是互补的——一个向前看、一个往回想。第二，anchor 特征使得 PPO 的 clip 机制自然地把搜索空间限制在 baseline 附近，这是一种隐式的信任域约束。第三，所有特征除以节拍时间做归一化，保证在不同大小的数据集上尺度一致。

> 这一页讲多目标奖励函数的标量化设计。
>
> 奖励由每步奖励和终局奖励组成。每步奖励采用尺度不变归一化——用 makespan 增量除以理想完工时间、负载增量除以理想负载值，保证在 290 个任务的数据集和 3000 个任务的数据集上，奖励的量级是一致的。这消除了传统 RL 中"换了数据集就要重新调超参"的问题。
>
> 终局奖励包含两个组件。第一个是节拍超期惩罚——如果新方案的完工时间超过了初始方案，惩罚就是超期比例。第二个是稳定性惩罚，由三个子项加权求和：开工时间偏离的均值、站位变更率、团队变更率。权重设置反映了物理实践中这三者的相对重要性——开工时间偏离一次影响最大，团队变更会带来沟通成本，站位变更影响相对最小，所以权重是 0.20:0.10:0.05。

>
> 底部的 Pareto 示意图展示了三个目标之间的权衡面。我们当前的权重配置倾向于优先保证完工时间，其次是开工偏离，最后才是站位的物理变动。

> 下面是对"为什么提升有限"的分析——这是我们坦诚面对的一个问题。三个因素按照影响程度排列。
>
> 最核心的因素是终局奖励的时序衰减问题。我们的节拍惩罚和稳定性惩罚只在 episode 的最后一步注入。GAE 机制通过 gamma 和 lambda 的乘积把终局信号反向传播——每一步衰减 0.9 的因子，经过 200 步后信号强度降到 10 的负 10 次方，在数值上等价于零。这意味着 episode 前 170 步的动作几乎收不到任何"你应该靠近 baseline"的梯度信号。模型在前半段完全按照初始排程的本能行事。
>
> 次要因素是新特征的冷启动——6 列从零开始的权重需要足够的学习量才能激活。第三个因素是延迟信号的稀疏性——只有 15% 的任务被标记为延迟，大部分数据中 delay 特征是零，模型难以提取到统计上有意义的模式。

## 附录：学术 PPT 制作规范建议

| 要素 | 学术风格建议 |
|:---|------|
| **配色** | 深蓝+白+灰为主，避免商业感强烈的渐变色和大面积色块。强调色仅在数据或关键公式处使用 |
| **字体** | 标题：思源黑体 / 微软雅黑 Bold 28pt；正文：思源宋体 / 微软雅黑 Regular 20pt；公式：Latin Modern Math / XITS Math 20pt |
| **公式** | 使用 PPT 原生公式编辑器（`Alt+=`），字体选择 Latin Modern Math（LaTeX 风格），变量用斜体、函数名用正体 |
| **数学符号** | 统一使用标准学术符号：标量斜体、向量粗体、集合大写花体。避免工程代码中的变量名 |
| **图表** | 用 matplotlib + LaTeX 字体渲染后导出 SVG/PNG 插入，背景透明。折线图不加网格线、散点图不加数据标签（除非极少点） |
| **表格** | 三线表风格（仅顶线、栏目线、底线），学术论文标准。灰底斑马纹可以，但不用彩色表头 |
| **动画** | 尽量不用动画。若必须用，仅用"淡入"（Fade）且时长 ≤ 0.3s |
